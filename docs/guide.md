## Сборка

Нужен Go 1.26.6+.

```bash
go build -o bin/ ./...
```

Четыре бинарника: `marvia-keygen`, `marvia-node`, `marvia-client`, `marvia-panel`.

Для Linux-ноды из-под Windows:

```bash
GOOS=linux GOARCH=amd64 go build -o bin/linux/ ./...
```

## Быстрый старт

**1. Ключи**

```bash
./bin/marvia-keygen
```

Приватный остаётся на ноде, публичный нужен клиенту.

**2. Нода**

```bash
MARVIA_SERVER_KEY=<приватный ключ> ./bin/marvia-node -listen :443 -tls-cert fullchain.pem -tls-key privkey.pem -cover https://example.org
```

Ключ передавай переменной окружения или `-key-file`: значение флага `-key`
видно в `ps` любому пользователю машины.

`-cover` — адрес настоящего сайта, который увидит всякий, кто зайдёт на домен
ноды браузером или сканером. **Это не украшение, а защита**: нода, молча
рвущая непонятные соединения, вычисляется активным зондированием за пару дней.

Куда нода не ходит по просьбе клиента — зашито и не настраивается: петля,
приватные подсети, link-local с метаданными облака (169.254.169.254), CGNAT,
multicast и порт 25. Покупатель — не хозяин машины, и заглядывать ей за
спину ему нечего; а SMTP без логина через VPN нужен только спамерам, за
которых нода отвечает баном у хостера. Проверяется адрес после разрешения
имени, так что домен, указывающий на 127.0.0.1, тоже не пройдёт. Клиент
получает статус «запрещено» и ошибку по-человечески. На одной сессии
одновременно живёт не больше 256 потоков: лишние закрываются сразу, чтобы
один ключ не выел память ноды.

### Маскировка REALITY

Вместо собственного сертификата нода может прикрываться чужим настоящим
сайтом. Тогда свой домен и сертификат не нужны вовсе.

```bash
./bin/marvia-keygen -reality
```

```bash
MARVIA_REALITY_KEY=<приватный ключ> ./bin/marvia-node -listen :443 \
  -reality-dest www.samsung.com:443 -reality-sni www.samsung.com \
  -panel https://panel.example.com -panel-token <токен ноды>
```

Как это работает: на каждое входящее соединение нода открывает своё к сайту
прикрытия и зеркалит туда ClientHello. Тот, кто не доказал право входа,
получает **настоящий чужой сайт** — его содержимое и его подлинный
сертификат. Отличить ноду от зеркала того сайта нельзя, потому что в этот
момент она им и является.

Проверено вживую: `curl` с полной проверкой сертификата (`ssl_verify_result 0`)
подключился к ноде, прикрытой `www.example.com`, и получил страницу, побайтно
совпадающую с настоящей.

Приветствие клиента несёт метку времени, и нода узнаёт его, только если
время расходится с её часами не больше чем на пять минут. Записанное
приветствие, повторённое позже, получает сайт прикрытия, а не ноду: так
цензор не проверит сервер чужим ClientHello. Цена — покупатель, у которого
часы на телефоне ушли дальше пяти минут, не подключится, пока не включит
время по сети. Это же касается VLESS с REALITY из чужих приложений.

Чем это лучше обычного TLS с нашим сертификатом:

| | Свой сертификат | REALITY |
|---|---|---|
| Отпечаток ответа | стандартный Go, отличается от nginx | берётся у настоящего сайта |
| Свой домен | нужен, блокируется по SNI | не нужен вовсе |
| Что видит сканер | наш сайт-заглушку | чужой популярный сайт с валидным замком |
| Продление сертификата | нужно | не нужно |

**Как выбирать сайт прикрытия.** Он должен поддерживать TLS 1.3 и HTTP/2, быть
популярным, не принадлежать тебе и не лежать в подсети ноды. Плохой выбор
выдаёт ноду: сайт, к которому из этой страны никто не ходит, сам по себе
аномалия.

**Несколько имён вместо одного.** `-reality-sni` принимает список через
запятую:

```bash
-reality-dest www.samsung.com:443 -reality-sni www.samsung.com,www.lg.com,cdn.example.net
```

Одно имя на ноду — это одна строка в списке блокировок: зарезали домен, и нода
умерла целиком, хотя её адрес жив. С набором блокировка одного отнимает у неё
долю соединений, а не все.

Вписывать этот набор куда-то ещё не надо: **нода сообщает его панели сама**,
вместе с очередным отчётом о расходе. Сменил флаг, перезапустил ноду — панель
догонит за несколько секунд. В карточке ноды имена показаны, но не правятся:
поле для правки означало бы, что вписанное переживёт следующий отчёт, а оно
не переживёт.

Дальше панель раздаёт набор клиентам, и клиент выбирает имя на каждое
соединение; сессии живут 20…60 минут, так что имя меняется само несколько раз
в сутки.

Работает это только под REALITY. При обычном TLS и за CDN имя в SNI обязано
совпадать с сертификатом, поэтому поля там нет и выбирать не из чего.

`-reality-short-id` — короткие идентификаторы клиентов через запятую,
шестнадцатеричные. Позволяют отзывать группы клиентов, не меняя ключ ноды.

Публичный ключ REALITY нода печатает при запуске — его нужно вписать в панель
как `pbk`, чтобы в ссылки уходило `security=reality`.

**Наш клиент тоже умеет REALITY.** Клиентская сторона написана вручную:
готовой библиотеки не существует, `github.com/xtls/reality` — только сервер,
а клиент живёт внутри Xray-core, тащить который в мобильное приложение
целиком неразумно.

```bash
./bin/marvia-client -server <адрес ноды>:443 -sni www.samsung.com \
  -reality-pbk <публичный ключ REALITY> -reality-sid <идентификатор> -pubkey <ключ ноды>
```

Правильность проверяется единственным осмысленным способом — живым
разговором с эталонным сервером. Тест `TestRealityClientAcrossFingerprints`
гоняет клиента против того самого `xtls/reality`, который используют Xray и
sing-box, на восьми отпечатках браузеров сразу.

Он же поймал настоящую ошибку. Свежие отпечатки Chrome шлют два обмена
ключами: гибридный постквантовый и обычный X25519. Нода сначала ищет обычный
и только при его отсутствии берёт половину гибрида — клиент делал наоборот,
и на Chrome 131 и новее общий секрет расходился. Проявлялось это худшим
образом: нода не узнавала клиента и молча отправляла его на сайт прикрытия,
то есть «интернет не работает» без единой внятной ошибки.

### Работа за CDN: адрес ноды не существует

REALITY прячет трафик, но не адрес. Под ковровую блокировку диапазонов
хостингов — как 4 августа 2026 года — попадает и безупречно замаскированная
нода, потому что её никто не разглядывал.

Ответ на это один: **не показывать адрес вовсе**. Пользователь подключается к
адресам CDN, за которыми живут миллионы обычных сайтов; заблокировать такой
диапазон целиком означает уронить пол-интернета.

```bash
./bin/marvia-node -listen :443 -ws-path /assets/app.js \
  -tls-cert fullchain.pem -tls-key privkey.pem -cover https://example.org
```

Домен направляешь на CDN, CDN — на ноду. В конфиге покупателя стоит домен, а
не адрес сервера.

```bash
./bin/marvia-client -server <адрес CDN>:443 -ws-host <домен> -ws-path /assets/app.js -pubkey <ключ>
```

Проверено вживую: 11 запросов пользователя прошли через одно соединение до
ноды — мультиплексирование работает и внутри WebSocket.

Весь путь покупателя держит сквозной тест
`TestABuyerBehindCDNConnectsWithoutKnowingTheNodeAddress`
(`cmd/marvia-node/cdn_e2e_test.go`): панель выдаёт доступ и подписку, в
подписке только адрес CDN, клиент проверяет сертификат CDN, проходит через
обратный прокси и WebSocket к ноде, VP1 доводит байты до цели и обратно, а
тот же путь без WebSocket отдаёт сайт-прикрытие. Тест локальный: настоящий
CDN и сеть из России он не заменяет.

**Путь стоит делать неочевидным.** Перебор популярных вроде `/ws` или `/vless`
по всем адресам хостера — дешёвый способ искать ноды. При этом сам по себе
путь туннеля ничем не выделяется: запрос без переговоров о WebSocket получает
ровно то же, что и любой другой путь.

| Путь | Что отдаёт нода |
|---|---|
| `/` | сайт-прикрытие, 200 |
| `/ws`, `/vless`, `/api` | сайт-прикрытие, 404 |
| путь туннеля обычным запросом | сайт-прикрытие, 404 |
| путь туннеля с переговорами | туннель |

**CDN видит расшифрованный трафик** — он же терминирует TLS. Здесь окупается
слоёная архитектура: внутри WebSocket работает VP1 со своим шифрованием, и CDN
достаётся поток, который он прочитать не может.

**REALITY и CDN несовместимы.** REALITY требует прямого TCP до ноды, а CDN
расшифровывает TLS у себя. Это два ответа на две разные угрозы:

| Режим | Что прячет | Чем платим |
|---|---|---|
| REALITY на чистом адресе | трафик неотличим от чужого сайта | адрес виден, попадает под ковровые блокировки |
| WebSocket за CDN | адреса для цензора не существует | камуфляж слабее, CDN видит зашифрованный нами поток |

Продавец выбирает под конкретную ноду; панель собирает ссылки под оба режима.

**3. Клиент**

```bash
./bin/marvia-client -server <домен>:443 -sni <домен> -pubkey <публичный ключ>
```

**4. Проверка**

```bash
curl -x socks5h://127.0.0.1:1080 https://api.ipify.org
```

Должен вернуться IP ноды. Схема именно `socks5h`: `h` означает, что домен
резолвит нода, иначе DNS-запросы уйдут мимо туннеля и выдадут всё, что ты
открываешь.

Проверить прикрытие — должен открыться сайт из `-cover`:

```bash
curl https://<домен>/
```

### Локальная проверка целиком

На Windows из PowerShell:

```powershell
.\scripts\smoke.ps1
```

На Linux, macOS и в Git Bash:

```bash
bash scripts/smoke.sh
```

Поднимает ноду и клиента на localhost с самоподписанным сертификатом и
проверяет три вещи: трафик через туннель ходит, мультиплексирование работает,
посторонний видит сайт-прикрытие.

### Отладка вручную

```bash
./bin/marvia-node -key <приватный> -tls-self-signed cover.local -cover https://example.com
./bin/marvia-client -server 127.0.0.1:8443 -sni cover.local -insecure -pubkey <публичный>
```

Флаг `-plain` с обеих сторон отключает маскировку целиком — удобно, когда
отлаживаешь сам протокол и не хочешь мешать слои.

## Клиент для Windows

Для обычной установки скачайте `marvia-windows-setup.exe` в новых выпусках
и запустите его. Установщик размещает приложение и Wintun в выбранной папке,
создаёт ярлык в меню «Пуск» и запись удаления. Настройки и ключи в
`%APPDATA%\Marvia` сохраняются при обновлении и удалении. Перед установкой
завершите работающую Marvia через «Выйти» в трее. Запрос прав администратора
при запуске VPN остаётся штатным: установщик его не обходит.

Для окна также нужен Microsoft Edge WebView2 Runtime. Marvia проверяет
официальные ветки установки до запроса UAC и автоподключения. Если Runtime
не найден, предлагает открыть [страницу Microsoft](https://developer.microsoft.com/microsoft-edge/webview2/#download-section)
и завершает запуск. Установите Evergreen Runtime и повторно откройте Marvia.
Установщик Marvia не содержит полного Runtime. Даже при установленном движке
ошибка создания окна завершает программу с очисткой туннеля; ключи сохраняются.

Готовый переносимый комплект — `marvia-windows.zip`.
Распакуйте **весь архив** в одну папку и запускайте EXE из неё, не из ZIP.
Внутри находятся `marvia-windows.exe`, официальный подписанный `wintun.dll`,
лицензия драйвера и инструкция. Один EXE открывает окно, но без DLL рядом
не сможет создать VPN-адаптер. Старые выпуски могут содержать только EXE.

Чтобы упаковать самостоятельно собранный EXE:

```powershell
./scripts/package-windows.ps1 -Exe ./marvia-windows.exe -OutputDirectory ./dist -Version 0.13.0-alpha.1
```

Сценарий сверяет SHA256 официального архива Wintun; на Windows дополнительно
проверяет подпись DLL. Для сборки установщика нужен компилятор NSIS (`makensis`
в PATH или параметр `-MakeNSIS`). Релизная сборка добавляет установщик и ZIP.

```bash
go run github.com/tc-hib/go-winres@v0.3.3 make --arch amd64 --in cmd/marvia-windows/winres.json --out cmd/marvia-windows/rsrc
go build -ldflags "-H windowsgui" -o marvia-windows.exe ./cmd/marvia-windows
```

Рядом с получившимся файлом нужен `wintun.dll` — драйвер сетевого адаптера от
WireGuard. Берётся с [wintun.net](https://www.wintun.net/), в архиве нужна
папка `bin/amd64`. Перед тем как класть его рядом со своим кодом, стоит
проверить подпись:

```powershell
Get-AuthenticodeSignature .\wintun.dll | Format-List Status, SignerCertificate
```

Должно быть `Valid` и `CN=WireGuard LLC`.

Запуск — из PowerShell **от имени администратора**:

```powershell
.\marvia-windows.exe
```

Права нужны не для красоты: без них Windows не даёт ни создать сетевой
адаптер, ни трогать таблицу маршрутов. Программа проверяет это первым делом и
говорит прямо, а не падает где-то в середине.

### Окно, а не командная строка

Логотип встроен в EXE: его показывают Проводник, панель задач и трей.
Системного заголовка у окна нет: верхняя полоса — шапка самой программы, её
рисует образ вместе с кнопками окна (у macOS — светофор слева, у Windows 98 —
серые выпуклые). За пустое место шапки окно перетаскивают и прижимают к краям
экрана, двойной щелчок разворачивает, верхний край тянет размер, как и три
остальных. Раньше системная полоса красилась самым тёмным цветом темы и
стояла над шапкой — две полосы, верхняя почти чёрная. Меню кнопки «развернуть»
с раскладками Windows 11 при наведении не появляется; Win+Z работает.
После перезапуска Проводника значок трея восстанавливается.

### SmartScreen: почему Windows предупреждает

**Что это.** «Система Windows защитила ваш компьютер» — SmartScreen. Он
смотрит не на то, что внутри файла, а на его репутацию: подписан ли он
сертификатом издателя и много ли его уже скачали. Новый неподписанный файл
он встречает этим окном всегда, даже совершенно чистый. Антивирус —
отдельная проверка, и окно SmartScreen — не её находка.

**Что нажать.** «Подробнее» → «Выполнить в любом случае». Окно бывает один
раз — на `marvia-windows-setup.exe`. Установщик раскладывает программу сам,
и у установленного файла уже нет пометки «скачан из интернета», поэтому при
запуске SmartScreen больше не спрашивает. С ZIP иначе: пометка переходит на
всё, что из него распаковано, и спросить может при первом запуске
`marvia-windows.exe`. Поэтому качать стоит установщик.

**Какие файлы в выпуске.** `marvia-windows-setup.exe` — установщик:
приложение, подписанный WireGuard драйвер `wintun.dll`, ярлык, удаление
через «Приложения». `marvia-windows.zip` — тот же набор без установки.
Отдельного EXE в выпуске больше нет: без `wintun.dll` рядом он не поднимал
туннель, и скачавший его получал программу, которая не работает.

**Как проверить файл.** Суммы всех файлов выпуска подписаны через Sigstore
сборкой этого репозитория — см. README, «Как проверить, что файл
настоящий». Это доказывает, что установщик собран из открытого кода на
GitHub, а не подменён по дороге; SmartScreen об этом не знает.

**Как убрать окно по-настоящему.** Только подписью Authenticode от
доверенного центра — самоподписанный сертификат не помогает. Пути, от
дешёвого к дорогому:

- **SignPath Foundation** — бесплатная подпись для открытых проектов: файлы
  подписываются в GitHub Actions, сертификат выдан фонду. Проект под AGPL
  подходит; заявку подаёт владелец репозитория на signpath.org.
- **Сертификат Certum для открытых проектов** — недорогой сертификат на
  физическое лицо с подписью из облака.
- **winget** — установка командой `winget install` не ставит на файл
  пометку «из интернета», и окна нет вовсе. Манифест для выпуска пишет
  `scripts/winget-manifest.sh` — по сумме установщика из `SHA256SUMS`
  уже опубликованного выпуска, а не локальной сборки. В каталог winget он
  попадает запросом в репозиторий microsoft/winget-pkgs со своей учётной
  записи; пока запрос не принят, `winget install Marvia.Marvia` не
  работает, и README его не обещает.

  ```bash
  scripts/winget-manifest.sh v0.13.0-alpha.30 out
  winget validate --manifest out/manifests/m/Marvia/Marvia/0.13.0-alpha.30
  ```

  Дальше — форк microsoft/winget-pkgs, каталог `manifests/m/Marvia` из
  `out` в него и запрос на слияние; проверку там проводят их роботы, они
  же ставят установщик в песочнице. Установщик для этого ставится тихо
  (`/S`) и не останавливается на вопросах: на «Marvia сейчас работает» он
  выходит с кодом 2, и winget говорит «программа запущена».

Даже с подписью репутация копится по скачиваниям, и первые сборки могут
ещё предупреждать — так устроен SmartScreen, см.
[документацию Microsoft](https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/smartscreen-reputation).

Двойной щелчок по `marvia-windows.exe` — Windows спросит разрешение, откроется
окно с большой кнопкой. Ничего запускать из PowerShell не нужно: программа
видит, что прав нет, и просит их сама, обычным системным окном согласия.

Повысить права работающему процессу Windows не умеет — можно только запустить
новый. Поэтому программа перезапускает себя и тихо выходит; человек видит
привычное окно, а не совет открыть консоль.

Внутри окна — обычная страница, которую отдаёт сама программа, а показывает
встроенный в Windows движок WebView2. Своего набора виджетов мы не тащим: он
потребовал бы компилятора C, весил бы больше самого ядра и выглядел бы
одинаково чужим на всех системах. Если движка нет, запуск завершается до
автоподключения и предлагает официальную страницу установки Runtime.

Внешние ссылки открываются через проводник, а не напрямую. Программа
работает с правами администратора, и браузер, запущенный из неё, унаследовал
бы их: Chrome и Edge в таком виде просто отказываются открываться, а если бы
открылись — это был бы браузер с правами администратора, чего быть не должно.

**Страница закрыта одноразовым ключом в адресе.** Слушаем мы только петлю, но
этого мало: по одному из адресов отдаётся ссылка доступа с личным ключом
покупателя, а на компьютере может работать что угодно, в том числе чужое.
Ключ рождается при запуске и живёт до выхода.

**Ссылка `marvia://` не заменяет стоящий ключ молча.** Открыть такую ссылку
может любая страница в браузере, и подменённая увела бы весь трафик на
серверы того, кто её подсунул, — а заметить это нечем. Поэтому, когда ключ
уже есть и ссылка другая, программа спрашивает системным окном; «нет» стоит
по умолчанию. Первую ссылку, когда ключа ещё нет, берёт без вопросов — это
обычная настройка после оплаты. На телефоне так было с самого начала.

### Что в окне

Пять вкладок: туннель, серверы, диагностика, тема, настройки. Всё про
проверку и исправление — в «Диагностике» (см. ниже), журнал тоже там.
Подключение, вид и звук, программа и «о программе» — разделы настроек: слева
список с иконками, справа открыт один, выбор запоминается. Окно 1180×720.
Вид окна выбирают на странице «Тема» → «Вид окна», отдельно от образа:
образ меняет цвета, вид — главную и список стран. По умолчанию — «Marvia».

На главной «Marvia» — кнопка с ореолом, состояние и под ним нода капсулой с
откликом; справа «Сегодня» по часам, скорость приёма и отдачи с бегущим
графиком за полминуты, плитки «Сессия» и «Отклик ноды», неделя или месяц.
Страны на «Серверах» — строками: точка состояния, имя и подпись, полоска
качества и отклик; «Автовыбор» — первой строкой.

В виде «Карточки» под состоянием две карточки. «Где вы»: код страны, страна
и город, отклик числом и словом (быстро, средне, медленно); нажатие
открывает выбор страны. «Подписка»: сколько дней осталось — меньше трёх
предупреждающим цветом, — полоса и остаток трафика; срок и квоту ядро
узнаёт при подключении, до него так и написано. Плиток «Сессия» и «Отклик
ноды» справа нет — они повторяли бы карточки. В обоих видах сверху справа —
карточка «От продавца», если продавцу есть что сказать; см. «Канал
продавца в окне».

Страны в виде «Карточки» — сеткой. Крупно двухбуквенный код страны (флаги
Windows рисует буквами, поэтому буквы честнее), название страны и город;
код продавца вроде «fi» превращается в «Финляндия». Отклик — числом, тремя
палочками и словом: быстро (до 120 мс), средне (до 300), медленно. Метки
говорят, где идёт трафик, что выбрано вами, кто не ответил и сколько длилось
подключение. «Автовыбор» — отдельной карточкой сверху. Страну код берёт из
того, что написал продавец; адрес ноды никуда не отправляется.

Тема — та же, что в панели продавца и на телефоне: 28 готовых видов, акцент,
свет (откуда светит, характер, густота тени, оттенок светлой стороны),
скругления, плотность, карточки, кнопка питания, свечение, три профиля и код
темы. Таблица и арифметика одни на всех, лежат в `internal/look/look.js` и
вшиваются в обе страницы при отдаче; правка там красит и панель, и окно, а
генератор переписывает таблицу для телефона. Выбор хранится на этом
компьютере и никуда не уходит.

Поверх темы окно предлагает пятнадцать образов — лентой в два ряда, она
листается мышью, а наборы над ней отбирают нужные. Наши: «Графит», «Точка» и
«Бумага» (точечное табло). В духе Windows: 11 тёмная и светлая (слюда над
обоями, полоска выбора у вкладки, Segoe UI), XP (синий глянцевый заголовок,
панель задач слева, зелёная кнопка «Пуск», Tahoma), 98 (бирюзовый стол, серые
выпуклые окна с синими полосками заголовков). В духе macOS: тёмная и светлая
(светофор, плавающая стеклянная боковая, Inter вместо SF). В духе Linux:
Ubuntu (баклажан, оранжевый крестик, шрифт Ubuntu), GNOME (Adwaita: круглые
кнопки, серая боковая панель, выбранный раздел плашкой акцента, белые
карточки с обводкой на сером фоне, кнопка питания в акценте), KDE Plasma (Breeze: шевроны, голубой фокус, Noto
Sans), Hyprland с палитрой Catppuccin Mocha, Nord и Gruvbox (плитки с
зазорами, цветная рамка активной, бар из капсул). У каждого свои обои,
нарисованные кодом: по мотивам систем, но ни одна не копирует их картинки.
Названия систем здесь — указание на стиль, знаки принадлежат владельцам;
программа с ними не связана. Шрифты Inter и Noto Sans (OFL) и Ubuntu (Ubuntu
Font Licence) вшиты, как остальные; шрифты Windows берутся из системы.
Прежние образы при обновлении переходят на ближайшие новые.

Образ «Прозрачная» показывает под окном обои рабочего стола — те, что стоят
у человека, — сдвинутые по месту окна на экране, как «Заполнение» у Windows:
окно выглядит прозрачным и продолжает стол вокруг себя. Окно сообщает
странице своё место при каждом сдвиге. Размытие и затемнение обоев — ручками
в точной настройке, по умолчанию почти без размытия. Системный Acrylic не
используется: он размывал слишком сильно, был только в новой Windows 11 и
белел, когда окно теряло фокус. Если у стола нет картинки, только цвет, —
нарисованный вид.

В точной настройке «Прозрачной» есть выбор «Под окном»: «Обои» — как
описано выше, или «Всё, что позади» — окно становится по-настоящему
сквозным, и под ним видно значки рабочего стола и другие окна. Размытия в
этом виде нет: страница может размыть только то, что нарисовала сама, а
рабочий стол рисует Windows. Читаемость держат затемнение и
полупрозрачные карточки. Виджет у трея всегда сплошной: без фона плашка
поверх чужих окон не читается. Если WebView2 слишком старый, режим не
включается, а причина пишется в журнал. Наверху вкладки «Тема» блок «Сделайте окно своим» ведёт к
трём главным способам: свои обои стола, своя картинка или видео фоном, точная
настройка.

В образах систем программа выглядит окном на рабочем столе: обои видны
рамкой вокруг, внутри — окно в манере системы со своей тенью и скруглением.
У Windows 11 оно из слюды — размытых обоев, у macOS из жидкого стекла:
обои под боковой панелью, карточками и кнопкой плывут, как под толстым
стеклом, свет на стёклах — неподвижный, сверху. За пустое место стола окно
тянут так же, как за шапку. Развёрнутое окно рамки стола не держит: во весь
экран это обычная программа. Крестик по умолчанию прячет окно в трей —
подсказка на нём говорит, что выйти можно из меню значка у часов.

«Точная настройка» под образами открывает всё поле за полем: основу, акцент и
оттенок (кружками или пипеткой на любой цвет), свои цвета фона, карточек,
текста, подписей и обводки, скругление, отступы и зазоры в пикселях, свечение,
размытие стекла и непрозрачность карточек, шрифты текста и надписи, подачу
цифр, размер и регистр надписи, знак (фирменный металл или цвет акцента), узор
с насыщенностью, шагом, размером, скоростью и своим цветом, свет и свой фон из
файла. Пустое поле — «как у образа»; ↺ возвращает его. Код темы переносит всё
это целиком: до «~» — общая часть, которую понимают панель и телефон, после —
образ и точная настройка окна.

Узор отвечает на курсор, при подключении по нему расходится волна, клик по
пустому фону пускает свою; кнопка питания тянется за курсором, карточки
наклоняются. В «Настройках → Вид и звук»: заставка при запуске, живость фона,
отклик на руку, волна по клику и звук подключения. Если в Windows включено
уменьшение движения, фон стоит и заставки нет. В покое и в свёрнутом окне фон
не рисуется вовсе.

Крестик окна по умолчанию прячет его в трей: туннель продолжает работать,
значок — у часов. В «Настройках → Программа» крестик можно заставить
закрывать программу — тогда он сначала отключает туннель, как «Выйти» в меню
значка.

Настройки открываются «Обзором»: что работает прямо сейчас — туннель и
нода с длительностью сессии, протокол и транспорт (VP1 поверх REALITY, TLS,
WebSocket или QUIC), шифрование (Noise IK: X25519, ChaCha20-Poly1305,
BLAKE2s), отклик ноды, резолвер и шифруются ли имена, адаптер Wintun с MTU и
IPv6, маршруты мимо туннеля, системный прокси, права администратора и
версия. Каждое значение — техническое, моноширинным, и под ним строка о том,
что это значит; полоска слева — работает, ждёт подключения или требует
внимания. Ниже — «Что обещано и что работает»: те же пункты, что README
называет готовыми и неготовыми; тест сверяет список «пока нет» в окне с
README, чтобы они не разошлись.

MTU — размер пакета на адаптере — в «Диагностике → Протокол и сеть»:
«Авто» (1500), 1420, 1380, 1280 или своё число от 1280 до 1500. Меньший MTU
помогает, когда снаружи режут крупные пакеты и сайты открываются наполовину;
новый размер действует со следующего подключения, как и DNS. Расход на
главной переключается между семью и тридцатью сутками — книга хранит месяц.

Чего в окне намеренно нет, хотя в макете было: split tunneling по
приложениям и добавление нод по ссылке. За этими кнопками нет действия —
ноды приходят из подписки. Нарисованная кнопка — обещание. Kill switch из
макета теперь есть — в «Подключении», см. ниже.

Под трафиком за сегодня — неделя: семь суток столбиками, итог, среднее за
день и самый занятый день. Считает сама программа, как телефон: у панели на
каждого человека только накопительный итог, и подённой истории покупателя
она не ведёт и вести не должна. Книга — тридцать суток по 24 часа в
`%APPDATA%\Marvia\traffic.json`, по местному времени компьютера; файл
прежней версии с одними сутками читается как книга из одного дня. Мимо
туннеля трафик не считается — как и на телефоне. Месяца и недели по часам,
как на вкладке «Расход» телефона, в окне пока нет — книга их уже хранит,
экрана нет; долей стран нет совсем — книга не помнит, через какую страну
шёл трафик.

### Диагностика

Отдельная вкладка слева, между «Серверами» и «Темой»: всё, что про проверку
и исправление, в одном месте. Главная от неё свободна: там туннель и трафик.

**Где вы в интернете.** Адрес и страна — ответ
`www.cloudflare.com/cdn-cgi/trace`, полученный через ноду, — и сервер, к
которому подключены.

**Качество связи.** Отклик, джиттер и потери за последние пять минут (те же
замеры, что у плитки «Отклик ноды») и как именно подключено: протокол (VP1
или протокол чужой ссылки — VLESS, Trojan…), транспорт (TLS, REALITY,
WebSocket за CDN или QUIC с запасным TCP; у чужих — raw, ws, grpc, xhttp и
защита tls или reality), имя прикрытия (SNI) и сколько запасных у REALITY,
отпечаток TLS, MTU, DNS и шифруются ли имена, дробление и IPv6 — те, с
которыми поднят туннель. Всё это говорит сама программа, тем, с чем
дозванивается ядро; без туннеля строк нет. Раньше чужой ключ в «Обзоре»
выглядел как «VP1 · TLS» — теперь там его протокол.

**Утечка адреса.** Окно узнаёт адрес дважды: обычным путём Windows, как
браузер, и через ядро туннеля. Разные адреса значат, что часть трафика идёт
мимо VPN и сайт видит настоящий адрес. Если в туннеле выключен IPv6, окно
ещё пробует открыть соединение по IPv6 обычным путём: туннель такие
сбрасывает сам, и открывшееся ушло мимо него. На утечку — кнопки «Включить
kill switch» и «Починить». Настоящего адреса в ответе нет и на экране тоже:
снимок окна пересылают продавцу.

**Проверить всё.** Девять шагов по порядку, от провода к сайту: интернет без
VPN (TCP до 1.1.1.1 и 8.8.8.8 мимо туннеля), запросы имён, отвечают ли
серверы по TCP и сколько миллисекунд у лучшего, поднято ли подключение,
идёт ли браузер через туннель (страница двумя путями — через Windows и через
ядро, как проверка после подключения), какой адрес видит интернет, не
утекает ли адрес, сколько главных сайтов открылось и помехи рядом (второй VPN, Hiddify,
подключённый WARP, системный прокси). Каждый шаг появляется, как только
ответил. У плохого шага — кнопки с настоящим действием, и только там, где
оно есть: «Починить» (то же, что на главной), «Сменить сервер» (ведёт на
«Серверы»), «Включить дробление» и «Сменить DNS» (меняют настройку и
переподключают), «Переподключиться», «Подключиться», «Убрать прокси». Где
Marvia помочь не может — нет интернета вовсе или прокси прописан в
переменных окружения, — кнопки нет, только слова. Программа отдаёт коды и
числа, слова — у окна на его языке; тест сверяет, что у каждого шага есть
слова на обоих языках, а у каждого действия — кнопка с делом. В конце —
«Скопировать отчёт продавцу», тот же отчёт без ключей и адресов.

**Скорость.** Качает через туннель до 30 МБ с `speed.cloudflare.com`, не
дольше пяти секунд, — из трафика подписки, поэтому только по кнопке. Число
крупно, рядом последние восемь замеров столбиками; история лежит в
localStorage окна на этом компьютере.

**Сайты.** «Проверить сайты» открывает через туннель Google, YouTube,
Telegram, WhatsApp, Instagram, ChatGPT, X и GitHub и показывает у каждого ✓ со
временем ответа или ✗; любой HTTP-ответ, даже редирект на вход, считается
«открылся». Адрес, сайты и скорость идут через ядро туннеля, мимо браузера и
адаптера: ответ — про сам туннель.

**Протокол и сеть.** Дробление приветствия, «Только TCP», DNS и его
шифрование, MTU, IPv6 и «Переподключить», чтобы выбранное подействовало
сразу. Переехали сюда из «Настроек → Подключение»: здесь их меняют, глядя на
то, что в работе. «Только TCP» — к нодам Marvia без пробы QUIC: откат на TCP
ловит сеть, где UDP закрыт, но не ту, где его душат после первых мегабайт.
У чужого ключа QUIC от Marvia нет, и строки нет.

**Отпечаток TLS.** Чьим браузером представляться ноде Marvia: «Как у
продавца» (по умолчанию — тот, что продавец выбрал для ноды в панели) или
Chrome, Firefox, Safari, iOS, Android, Edge. Только руками и только для
ключей Marvia: у чужой ссылки отпечаток записан в ней самой. Сама программа
отпечаток не перебирает — смена сразу после заморозки адреса, по
наблюдениям 2026 года, её удлиняет. Выбор нужен там, где фильтр режет именно
одно приветствие, а продавец этого из-за границы не видит. В «Качестве
связи» у отпечатка пометка — «выбрал продавец» или «выбрали вы», в отчёте
продавцу — тоже.

**Журнал** — последние строки того, что делала программа, и «Скопировать
отчёт».

Когда нода сменилась сама, потому что прежняя замолчала, внизу окна на
несколько секунд всплывает «Нода «…» не отвечала — теперь «…»»; при выборе
руками — «Нода сменилась: …».

Плитка «Отклик ноды» живая: программа пингует текущую ноду раз в пять секунд
тем же служебным кадром, что и надзор, и показывает медиану последних
ответов, полоски последних двух с половиной минут (красная — ответа не было),
разброс отклика (джиттер) и долю потерь за пять минут.

### Ключи от двух продавцов сразу

Как подписки на телефоне: на вкладке «Серверы» — список сохранённых, рабочий
один и отмечен; в его строке срок и остаток трафика, когда панель их
сообщила. Щелчок по строке делает ключ рабочим. Поле для новой ссылки
открывается кнопкой «+ Добавить ключ» — ссылка рабочего ключа в нём не стоит,
в ней личный ключ. Если в буфере обмена лежит ключ доступа (marvia://, ссылка
чужой ноды или адрес, похожий на подписку), а в списке его ещё нет, над
списком появляется «В буфере ключ доступа» с видом и хостом и кнопкой
«Вставить»: ссылка встаёт в поле, сохраняет её человек сам. Буфер читает
программа, а не страница, и только когда открыты «Серверы» или нажато
«Добавить». «Сохранить» кладёт вставленную ссылку в список и делает её рабочей;
имя необязательно — без него берётся метка из ссылки или домен продавца, он
и отличает продавцов друг от друга. Та же ссылка второй раз не двоится.
Смена рабочего и «Сохранить» с новым ключом переподнимают поднятый
туннель: ключ другой, а с ним ноды и продавец, и держать трафик на прежнем,
показывая новый, значило бы врать. «Убрать» — в два нажатия; убрали рабочий — программа
остаётся без ключа и опускает туннель, а не переходит на соседний втихую.

Рабочий ключ по-прежнему лежит в `%APPDATA%\Marvia\account` — его читают
автозапуск и трей, а старая версия при откате найдёт его на прежнем месте.
Список — рядом, в `keys.json`, тоже только для владельца. Окно получает
список без ссылок, по отпечаткам: в ссылке личный ключ, и гонять её
туда-обратно ради кнопки незачем. Кэш списка нод у каждого ключа свой
(`client.CacheFile`, то же имя файла, что на телефоне), поэтому смена
ключа туда-обратно не стоит похода в панель; у убранного ключа кэш
стирается. Общий `subscription.json` прежних версий при первом запуске
переезжает в файл рабочего ключа, если отпечаток адреса подписки совпал.

### Чем отличается от marvia-client

`marvia-client` поднимает SOCKS5, и каждое приложение надо настраивать отдельно.
`marvia-windows` забирает весь трафик компьютера, как приложение на телефоне.
Ядро под ними одно и то же — включая выбор ноды по замерам с самой машины.

### Маршрут в обход туннеля

Самое важное место. Соединение до ноды обязано идти **мимо** туннеля: иначе
пакеты, которыми клиент разговаривает с нодой, попадут в тот самый туннель,
который к этой ноде и ведёт. Получится круг, в котором клиент ждёт ответа от
самого себя.

На телефоне это решается одной строкой — `addDisallowedApplication` на свой же
пакет. В Windows такого нет, и общесистемный маршрут до адреса ноды тоже не
годится: за CDN на том же адресе живут посторонние сайты, и они ушли бы мимо
туннеля. Поэтому мимо идут не адреса, а сами сокеты до ноды: `internal/netpath`
привязывает их к внешнему интерфейсу (`IP_UNICAST_IF`), и таблица маршрутов
системы остаётся без исключений.

Внешний интерфейс ищется по правильному признаку — сумме веса маршрута и веса
интерфейса. Считать только вес маршрута — распространённая ошибка: на машине
с вайфаем и проводом она уводит обход в интерфейс, которым система на самом
деле не пользуется.

### Российские сайты напрямую

Переключатель в настройках, раздел «Подключение». Банки, госуслуги и всё, что
не отвечает заграничным адресам, идут мимо туннеля — по тому же списку
российских подсетей, что и на телефоне: его отдаёт панель продавца по адресу
`/sub/{токен}/bypass`, программа хранит его рядом с ключом
(`%APPDATA%\Marvia\ru-routes.txt`) и спрашивает панель не чаще раза в неделю.

Устроено иначе, чем на телефоне. Там подсети исключает из туннеля система;
на Windows для этого пришлось бы вписать в таблицу маршрутов восемь тысяч
записей, которые переживут падение программы и сломаются при первой смене
Wi-Fi. Поэтому все пакеты по-прежнему приходят в мост, а он на каждое новое
соединение решает сам (`tunbridge.Split`): российский адрес получает
соединение через обычную сеть компьютера — тот же `netpath`, что держит
соединение с нодой, — остальное идёт в туннель. Отсюда два свойства:

- обход включается и выключается **сразу**, без переподключения: уже
  открытые соединения доживают по старому пути, новые идут по новому;
- после выхода в системе не остаётся ни одного следа.

Запросы имён мимо туннеля не уходят никогда, даже к российскому резолверу:
в открытую они выдали бы весь список посещённых сайтов. Трафик мимо туннеля
не попадает в его счётчики — как и на телефоне, где такие подсети до моста не
доходят вовсе.

Под переключателем — правда о списке: сколько подсетей уводится, «ещё не
скачан» или почему не скачался. У чужой подписки (VLESS, Trojan и прочих)
списка взять неоткуда: его даёт только панель Marvia, и окно так и говорит.

### Домашняя сеть мимо туннеля

Второй переключатель того же раздела, на той же развилке моста. Частные
адреса — `10.x`, `172.16–31.x`, `192.168.x` и их IPv6-пара `fc00::/7` — идут
напрямую. Свою подсеть Windows и без того ведёт мимо туннеля: её маршрут
точнее половин `/1`, которыми туннель забирает трафик. Переключатель нужен
для остального частного — соседней подсети за роутером, сетевого диска,
камеры, — которое иначе ушло бы на ноду за границей и там пропало.

Выключен по умолчанию, как на телефоне: в чужом Wi-Fi «домашняя сеть» — это
чужая сеть, и пускать туда трафик мимо туннеля человек решает сам.

### Свои сайты по имени

Два списка того же раздела, пустые по умолчанию: «Свои сайты мимо туннеля»
и «Свои сайты всегда через туннель». Вписывать можно как удобно — имя,
адрес из строки браузера, `*.gosuslugi.ru`, кириллицей; программа приводит
его к имени и показывает уже приведённым. Имя действует вместе со всеми
поддоменами: `sberbank.ru` уводит и `online.sberbank.ru`. Сайт живёт в одном
списке: вписанный в один пропадает из другого. Правила хранятся в
`%APPDATA%\Marvia\settings.json` и действуют сразу, без переподключения.

Порядок решения на каждое соединение: сперва правило по имени, потом
российский список и домашняя сеть. Самое точное правило сильнее общего —
можно увести мимо туннеля всю зону `ru` и оставить в туннеле `vk.ru`. Если
адрес общий у двух сайтов из разных списков (бывает на CDN), побеждает
туннель: сайт откроется, только из другой страны, — а не уйдёт мимо туннеля
то, что велено прятать.

Решает тот же мост (`tunbridge.Sites`), а он видит адреса, а не имена. Имя
соединения он узнаёт двумя путями:

- **из ответов на запросы имён.** Все они проходят через мост, и адрес из
  ответа запоминается за спрошенным именем — не меньше чем на 10 минут и не
  больше суток, что бы ни назвал резолвер. Так решаются все соединения к
  этому адресу: любой порт, TCP и UDP;
- **из TLS-приветствия (SNI)** на порту 443. Это нужно браузерам: Chrome,
  увидев у адаптера резолвер Cloudflare или Google, сам переходит на их DoH,
  и мост не видит ни одного имени. Приветствие мост только читает и отдаёт
  дальше байт в байт. Имя из приветствия точнее памяти и потому сильнее её.
  Цена — соединение на 443 открывается после первого пакета приложения, а не
  сразу; для TLS это доли миллисекунды. Протокол, где первым говорит сервер,
  ждёт секунду. Без правил мост приветствия не ждёт вовсе.

Чего правила не умеют:

- **ECH.** Браузер с DoH может зашифровать приветствие и показать наружу
  общее имя вроде `cloudflare-ech.com`. Тогда правило по имени сайта не
  сработает, и соединение решится по адресу — как без правил;
- **первый QUIC.** HTTP/3 идёт по UDP, и имени в нём мост не читает. Адрес,
  узнанный из ответа на запрос имени или из SNI соединения TCP, запоминается,
  и QUIC к нему идёт той же дорогой; браузер начинает сайт с TCP, так что
  обычно к QUIC адрес уже известен. Но если браузер узнал имя сам и сразу
  пошёл по QUIC, первое соединение решится по адресу.

Запросы имён по-прежнему не уходят мимо туннеля, даже для сайтов из списка
«мимо»: иначе список посещённых сайтов увидел бы провайдер. Память «адрес →
имя» живёт только в памяти программы — то же, что и так лежит в кэше имён
Windows, — и на диск не пишется. В отчёт для поддержки уходит только число
правил, не сами сайты.

### Kill switch

Третий переключатель раздела, выключен по умолчанию. Маршруты `/1`
забирают трафик в адаптер, но это договорённость, а не запрет: пропал
адаптер — пропали и маршруты, и программы идут напрямую. Своя подсеть,
программа, привязавшая сокет к Wi-Fi, рассылка запросов имён по всем
адаптерам — всё это обходит маршруты и при живом туннеле. Запрет ставит
фильтр самой Windows, Windows Filtering Platform (`internal/killswitch`).

Фильтр встаёт вместе с адаптером и стоит до «Отключить». Замолчала нода,
переезд не удался, адаптер пропал — он на месте, и мимо туннеля не идёт
ничего, пока туннель не вернётся или человек не нажмёт «Отключить». До
первого подъёма туннеля фильтра нет: окно говорит «не подключено», и
человек знает, что идёт напрямую.

Пропускается:

- сам Marvia — куда угодно. Соединения с нодой, российские сайты и
  домашняя сеть по развилке моста, запросы к панели делает наш процесс,
  поэтому разрешать адрес ноды и российский список по адресам незачем:
  адрес ноды меняется при переезде, а разрешение по адресу открыло бы его
  всем программам. Чужие программы доходят до российских сайтов через
  адаптер и мост, то есть опять нашим процессом;
- всё через адаптер туннеля;
- петля — окно говорит с программой через `127.0.0.1`;
- DHCP и NDP, чтобы закрытый компьютер не потерял адрес в сети. DHCPv4
  наружу — на любой адрес, а не только широковещательно: продление аренды
  идёт серверу напрямую;
- домашняя сеть, если она выведена мимо туннеля: частные адреса, локальные
  адреса канала и рассылки (`224.0.0.0/4`, `ff00::/8` — по ним ищут принтер
  и телевизор), в обе стороны. Если не выведена — закрыта и своя подсеть,
  которую Windows без фильтра ведёт мимо туннеля маршрутом.

Запросы имён (порт 53) мимо туннеля закрыты всегда, и при открытой
домашней сети: роутер отдал бы их провайдеру. Резолвер на петле и резолвер
туннеля работают. Всё прочее закрыто в обе стороны, IPv4 и IPv6.

Сессия WFP динамическая: фильтры живут, пока жив процесс, и система
снимает их сама, если Marvia убита или упала. Постоянные фильтры пережили
бы падение и оставили компьютер без сети до переустановки, и человек не
знал бы, что искать. Цена — после падения Marvia трафик идёт напрямую, как
без kill switch.

Включение, выключение и домашняя сеть действуют сразу, без
переподключения: новый набор правил встаёт раньше, чем снимается старый.
Смена рабочего ключа — это отключение и подключение, и на эти секунды
фильтр снимается. Не встал фильтр (служба фильтрации Windows не ответила) —
туннель всё равно поднимается, а под переключателем написано, почему
защиты нет: отказ подключаться оставил бы весь трафик напрямую, то есть
ровно то, от чего kill switch защищает.

Правила собирает чистая функция `killswitch.Plan`, и тесты проверяют их на
обещаниях — «браузер через Wi-Fi закрыт», «DHCP проходит», «имя у роутера
закрыто и при домашней сети» — без настоящего WFP. Раскладка структур WFP
закреплена при сборке, а машина проверки на Windows ставит весь набор
разрешений в настоящий фильтр (общий запрет там не ставится: машина живёт по
сети). На живом компьютере с оборванной нодой kill switch ещё не проверен.
Только для 64-битной Windows.

### Чей резолвер отвечает на имена

В «Диагностике → Протокол и сеть» — выбор DNS: Cloudflare, Google, Quad9,
AdGuard или свой адрес, как на телефоне. Запросы имён при любом выборе идут через туннель; выбор только в
том, кто на другом конце. Свой адрес проверяется до сохранения теми же
правилами, что на телефоне: четыре числа без ведущих нулей, и отдельно —
отказ адресу локальной сети, потому что из туннеля роутер не виден. Флаг
`-dns` остался для поддержки и отладки: он действует, пока в окне ничего не
выбрано.

Применяется при следующем подключении, и окно об этом говорит: адрес
резолвера стоит на адаптере и в политике имён системы (NRPT), а их меняют
только вместе с адаптером.

Ниже — переключатель «Шифровать запросы имён», включён по умолчанию. Что он
делает и чего не делает — в разделе «Запросы имён и нода» в части про
Android: ядро у обоих клиентов одно. Свой адрес шифровать нечем, и окно
пишет это под переключателем, а не делает вид, что шифрует. В журнале при
подключении — одна строка: имена идут к такому-то резолверу по HTTPS или
открытым DNS через туннель.

### IPv6 через туннель

Включён по умолчанию: адаптер забирает и IPv4, и IPv6 половинами адресного
пространства, иначе браузер обошёл бы туннель, выбрав AAAA-запись того же
сайта. Выключатель — как на телефоне, для случая, когда сайты путают
страну: IPv6-адрес ноды их базы порой относят не туда, куда IPv4. Мимо
туннеля IPv6 и тогда не уходит — маршрут остаётся, мост отвечает «адресов
IPv6 нет» (`tunbridge.Config.NoIPv6`), и программы идут по IPv4. Действует
со следующего подключения.

### Отчёты о доступности нод

Как на телефоне: при подключении по ключу Marvia замеры нод уходят панели
продавца, и она ставит выше те ноды, до которых люди доходят. Переключатель
оставляет замеры на компьютере; выбор ноды здесь от этого не меняется.
Чужим панелям отчёты не шлются никогда.

### Дробление приветствия

Тот же переключатель, что на телефоне: TLS-приветствие к ноде режется так,
чтобы имя из SNI не лежало целиком ни в одном TCP-сегменте, — против
провайдера, который режет по имени сайта. Режет ядро, одинаково для ключа
Marvia (`client.Options.Fragment`) и для чужих протоколов через Xray
(`foreign.Options.Fragment`). Выключено по умолчанию: без такого фильтра это
лишние пакеты и своя примета. Действует со следующего подключения — режется
дозвон до ноды, а он уже состоялся; «Переподключить» рядом применяет сразу.

### Только TCP

Рядом с дроблением, только для ключа Marvia: к нодам, объявившим QUIC, —
без пробы UDP (`client.Options.NoQUIC`). Откат на TCP и без того ловит сеть,
где UDP закрыт; эта строка — для сети, где он открыт, но его душат после
первых мегабайт, и QUIC дозванивается, а потом еле тянет. Выключено по
умолчанию: где UDP живой, QUIC ровнее на потерях. Телефон поля не задаёт и
ведёт себя как прежде.

### Трафик забирается двумя половинами, а не маршрутом по умолчанию

`0.0.0.0/1` и `128.0.0.0/1` вместе покрывают весь адресный простор и при этом
точнее, чем `0.0.0.0/0`. Прежний маршрут по умолчанию остаётся нетронутым: он
продолжает работать для того, что мы явно вывели в обход, а при выходе его не
надо восстанавливать, потому что мы его и не ломали.

При выходе снимаются ровно свои обходные маршруты, поимённо. Сбросить таблицу
маршрутов целиком — быстрый способ оставить человека без интернета вообще.

### Значок в трее и виджет

Крестик больше не выключает программу: окно уходит в трей, туннель живёт.
Раньше свернуть было некуда, и человек либо держал окно открытым весь день,
либо терял связь, закрыв его по привычке.

Нажатие на значок открывает виджет из макета — 380×560 без рамки, в углу у
трея: кнопка питания, состояние, нода (открывает серверы), три цифры и
ссылка в полное окно. Виджет прячется, как только человек нажал
куда-то ещё. Правая кнопка — меню: открыть, подключиться или отключиться,
выйти. Выход — только отсюда; он снимает маршруты и убирает значок.

Окно одно, шкуры две: тот же `app.html` с `?mode=widget` показывает виджет,
а без него — полное окно. Второго WebView2 нет намеренно: это два набора
памяти ради двух видов одной страницы. Переключает оболочка на Go: стиль
окна, размер, положение и адрес страницы; страница просит об этом запросом
`POST api/window`.

Значок и меню — напрямую через user32 и shell32, без сторонней библиотеки:
та потянула бы свой цикл сообщений, а он здесь уже есть, у окна WebView2.
Скрытое окно-приёмник живёт в том же потоке, и его сообщения раздаёт тот же
цикл. Иконка — из PNG прямо из байтов: с Vista user32 читает PNG как ресурс
иконки, отдельный .ico не нужен.

### Запуск вместе с Windows

Переключатель в настройках. Ставит задачу планировщика с
высшими правами, которая зовёт программу с `-tray`: без окна, в трее, и с
подключением, если ключ сохранён. Через планировщик, а не через ветку Run в
реестре: программа работает с правами администратора, и из Run она при
каждом входе показывала бы окно согласия — сразу после загрузки, когда
человек ещё ничего не нажимал. Задачу с высшими правами планировщик
запускает без вопросов, для этого он и существует.

### Канал продавца в окне

На главной, сверху справа, — карточка «От продавца»: напоминание о сроке,
объявление и кнопки «Продлить» и «Поддержка». Всё это продавец задаёт в
панели (см. «Поддержка, продление и объявление для покупателей»), а у чужой
подписки — заголовками `support-url`, `profile-web-page-url` и `announce`.
Кнопка появляется, только если ссылка есть: кнопка без адреса — обещание,
которого продавец не давал. Нет ничего — нет и карточки.

Карточка видна и без туннеля. «Продлить» нужнее всего ровно тогда, когда
подключиться нельзя: доступ кончился, и панель, может быть, не отвечает.
Поэтому окно берёт ссылки из кэша подписки, не ходя в сеть, а попытка
подключения кэш обновляет — в том числе неудачная, до отказа по сроку.
Сменили ключ — кнопки тоже от нового ключа: «Продлить» чужого магазина хуже,
чем никакого.

Адрес ссылки страница окна не получает и не шлёт — только имя кнопки;
открывает программа, через проводник обычного пользователя, а не из
процесса с правами администратора. Перед открытием ссылка проверяется ещё
раз: только `https://` и `tg://` и без кавычки, которая в командной строке
проводника закрыла бы аргумент. `tg://` открывает Telegram Desktop; если его
нет, Windows сама предложит, чем открыть.

Напоминание — за трое суток и за сутки до конца срока и когда трафика
осталось меньше десятой части; считает ядро (`client.Reminder`). «Понятно»
закрывает его, и ключ закрытого лежит в `%APPDATA%\Marvia\ui-reminded`: то
же самое не вернётся и после перезапуска, а следующая ступень — «остались
сутки» — или новый срок после продления покажутся заново.

Когда окно закрыто и программа в трее, то же напоминание всплывает
уведомлением Windows: через минуту после запуска и дальше раз в полчаса
программа проверяет срок и трафик. Каждая ступень всплывает один раз
(ключ показанного — в `%APPDATA%\Marvia\ui-tray-reminded`), а закрытое в
окне не всплывает вовсе. Нажатие на уведомление открывает окно с кнопкой
«Продлить».

### Чего пока нет

- приложений мимо туннеля, как на телефоне: Android делит трафик по
  приложениям сам, а на Windows для этого нужен фильтр по процессам (WFP) —
  его нет, и кнопки нет;
- «постоянного VPN», как на телефоне: пропавший адаптер программа сама
  заново не поднимает — kill switch держит сеть закрытой, а переподключает
  человек;
- недели по часам и долей стран в статистике — только месяц и неделя по
  дням и сегодня по часам;
- ключа с картинки QR-кода;
- «лимитной сети», частоты опроса и вида уведомления — на компьютере им
  нечего менять;
- подписи кода: SmartScreen пишет «неизвестный издатель». Бесплатный путь
  для открытых проектов есть — SignPath Foundation, заявку подаёт владелец;
  см. «SmartScreen: почему Windows предупреждает».

## Клиент для Android

Приложение лежит в `android/`. Собирается одной командой, ставится на телефон,
поднимает системный VPN.

```bash
scripts/android.sh
```

```powershell
.\scripts\android.ps1
```

Готовый пакет — `android/app/build/outputs/apk/debug/app-debug.apk`, 16 МБ,
`arm64-v8a` и `armeabi-v7a`.

Для эмулятора — `.\scripts\android.ps1 -Emulator`: ядро собирается ещё и
под x86_64. Без этого приложение на эмуляторе не запустить: ARM-библиотеку
на Go его транслятор роняет с SIGILL. В отладочную сборку x86_64 попадает,
в релиз — никогда, фильтр ABI в gradle это разводит.

Перед первой сборкой нужен `ANDROID_HOME` и однажды поставленный NDK:

| Что | Зачем | Размер |
|---|---|---|
| Android SDK: command-line tools, platform 36, build-tools 36 | сборка пакета | ~600 МБ |
| Android NDK 28 | `gomobile bind` без него не работает | ~2,2 ГБ |
| `gomobile` | превращает ядро на Go в библиотеку для Android | несколько МБ |

Отдельный плагин Kotlin подключать не нужно и нельзя: с девятой версии
сборщик Android умеет Kotlin сам и обрывает сборку, если увидит старый плагин.

### Что делает Kotlin, а что Go

Kotlin делает ровно две вещи, и обе платформенные: выпрашивает у системы
сетевой интерфейс и не даёт себя выгрузить из памяти. Выбор ноды,
рукопожатие, разбор пакетов, учёт — всё в Go, том же самом, что работает на
сервере и на настольной машине под SOCKS. Продублированная логика расходится,
и расходится она молча.

Даже проверка ссылки доступа на экране идёт через ядро,
`Mobile.checkAccountLink`. Правило, что считать правильной ссылкой, живёт в
одном месте — иначе приложение и сервер однажды разойдутся во мнениях, и
разбираться в этом будет человек, который просто хотел включить интернет.

Подключение Android можно отменить той же кнопкой, пока идёт выбор ноды.
Ядро сначала дозванивается до сервера, затем приложение создаёт VPN-интерфейс.
До появления состояния «Подключено» VPN ещё не защищает трафик: обычная сеть
остаётся доступной, если её не блокирует системная настройка Android
«Блокировать подключения без VPN».

При отключении сначала закрывается VPN-интерфейс. Очистка соединений и запись
истории выполняются в фоне и не удерживают главный поток приложения.
Поздний результат отменённого подключения или опроса не возвращает состояние
«Подключено». Проверка этих сценариев описана в
[отчёте 06.10.2026](android-checks/2026-10-06-stop.md).

### Экраны — по макету

Пять вкладок с таблеткой под активным значком: Туннель, Серверы, Расход,
Тема, Настройки. Первый запуск — два шага: язык, потом три разрешения от
Android (VPN, уведомления, не усыплять в фоне) с объяснением, зачем; без
VPN дальше не пустит, остальные два можно пропустить.

**Туннель.** Знак сверху (нажатие показывает имя и версию), диск с дугой —
дуга крутится, пока подключаемся, дорастает до трёх четвертей, когда
подключились, и гаснет в кольцо, когда выключено; состояния перетекают, а
не переключаются, у поднятого туннеля свечение дышит и искры на орбитах
ползут, — состояние, нода строкой, «Сегодня» по часам и две плитки: сессия
и скорость. Всё это живёт только на видимом экране: ушёл на другую вкладку
— кадры не жгутся.

**Серверы.** По провайдерам: у каждой подписки свои ноды, срок и остаток,
своё «обновить» и «замерить», сворачивается. Список виден и без туннеля —
ядро отдаёт подписку из кэша или панели (`Mobile.Subscription`,
`MeasureNodes`), кэш у каждой подписки свой. Выбор ноды руками
запоминается в приложении и передаётся ядру при подъёме: страна, выбранная
вчера, не сменится молча после перезагрузки.

**Расход.** Период 7 или 30 дней, кольцо из сегментов по дню, линия,
страны одной полосой долей, неделя по часам клетками.

**Настройки.** Одна страница: прокси по приложениям, подключение, маршруты
и DNS, приложение (язык, журнал, «О нас», «Сбросить всё»). Приложения и
журнал — подэкраны с «назад».

### Тема красится из кода

Вкладка «Тема» — предпросмотр сверху (настоящие экраны в масштабе:
главная, серверы, настройки, с переворотом при смене; на «Форме» — карточки
крупно во всю ширину, на «Ещё» — шапка со знаком в натуральную величину;
кадр наводится на настоящий элемент сцены после раскладки, так что плотность
и скругления видны, а край сцены в рамке не показывается), под ним вкладки
Цвет · Свет · Фон · Форма · Ещё. Ручки те же, что в панели и в окне на
компьютере: 28 готовых видов, акцент, свет, скругления, плотность,
карточки, кнопка, свечение, профили, код темы. Только на телефоне: узор
фона (точки, сетка, кольца, штрих), значок в шапке (Marvia, своя картинка,
скрыть) и шрифт — в общий код темы они не входят. Таблица одна: `internal/look/look.js`, из неё
`go generate ./internal/look` переписывает `LookTable.kt`, а тест в том же
пакете следит, что файл не отстал. Арифметика темы — смешение, контраст,
подбор приглушённого текста — переписана на Kotlin в `Look.kt`, и тест на
JVM сверяет её с движком на JavaScript по эталонным цветам.

Вьюхи красятся из кода, а не стилями. Стили и атрибуты темы Android читаются
один раз при надувании разметки; двадцать восемь видов с акцентом, которые
человек щёлкает и смотрит, как меняется экран, через них не сделать. Поэтому
вьюха говорит тегом, кто она — `card`, `dim`, `icon:acc`, — а `Paint`
обходит дерево и красит по тегу. Compose сделал бы то же дешевле на каждом
новом экране, но удвоил бы пакет ради пяти экранов, которые уже написаны.

Фон по свету рисует `Backdrop` — шейдерами, а не `GradientDrawable`: тому
доступны восемь направлений и круг без формы, а в look.js фон — CSS с углом
и эллипсом 130%×100%. Геометрия повторена та же, иначе телефон светил бы не
оттуда, откуда панель. Поверх градиента — зерно в пару единиц яркости:
тёмный градиент в восемь бит на цвет идёт кольцами, `DITHER_FLAG` на
аппаратном холсте шейдеры не трогает, а шум ломает границы ступеней ниже
порога заметности. Плитка 128×128 повторяется, а не считается на пиксель.

Шрифты вшиты: Onest, JetBrains Mono для цифр, Unbounded для имени,
Manrope и Geologica на выбор (все OFL, лицензия в `android/FONTS-OFL.txt`).
Системный Roboto не совпал бы с макетом ни в одной строке. Чего из макета
нет: видео-фона — свой плеер под фон это ExoPlayer и почти удвоение пакета.

### Код темы

В панели код вставляется в разделе «Вид» и применяется кнопкой «Применить
код» или клавишей Enter. При ошибке введённый текст остаётся для исправления,
текущий вид не меняется. Нажатие на свой код копирует его и показывает результат;
если браузер запретил буфер обмена, код можно выделить вручную.

Кнопка «Вернуть серый» возвращает исходные цвета, свет, скругления и плотность.
Сохранённые профили и свой фон остаются; фон убирается отдельно кнопкой «Убрать».
Серый старт и правила использования знака описаны в [бренде](brand.md).

Весь вид одной строкой вида `MV-PLU-FF5ECD-AURC-50-PIRO-GLNESH-54C8FF`:
пресет, акцент, свет и направление, густота тени, скругления и плотность,
кнопка, свечение и карточки, оттенок. Кодирует и разбирает его один и тот же
алгоритм в look.js и в `Look.kt`, тест на JVM сверяет оба на одних
примерах — код с телефона открывается в панели и в окне, и наоборот. Чужой
или битый код не применяется молча: приложение говорит, что это не код темы
Marvia. Профили — три слота с такими же кодами, на устройстве.

### Свой фон: картинка или видео

В панели и в окне на компьютере за интерфейс можно поставить свой файл —
фото или видео. Ручки три: как вписать (заполнить или целиком), затемнение
и размытие. Затемнение — пеленой цвета фона темы, а не чёрным: светлая тема
на тёмном снимке остаётся светлой, и текст, посчитанный под неё, читается.
Звук у видео выключен и включить его нечем.

Свой файл закрывает и образ, и обои стола: пока он стоит, смена образа фона
не меняет. Поэтому в окне на компьютере, пока файл стоит, наверху вкладки
«Тема» видна строка «Фоном стоит ваш файл» с кнопкой «Убрать», а «Мои обои
под окном» сами снимают свой файл.

Файл никуда не уходит. Он лежит в IndexedDB того браузера или окна, где его
выбрали: панель не принимает загрузок и не хранит чужих картинок на сервере,
а в код темы файл не попадает — код передают другому человеку, и обещать в
нём фон, которого у него нет, нечестно. Поэтому в другом браузере фона не
будет, и это ожидаемо. Потолок — 64 МБ: больше браузер не столько не
вместит, сколько подвесит вкладку на чтении.

На телефоне — фото, без видео и без размытия. Снимок выбирается системным
диалогом (`GetContent`: доступ к одному файлу, а не к галерее), уменьшается
до двух тысяч точек по длинной стороне и лежит в приватном каталоге
приложения; рисует его `BackdropImage` — снимок и пелена цветом фона темы,
той же геометрией, что в панели. Видео нет намеренно: его пришлось бы
крутить своим плеером, а это ExoPlayer и почти удвоение пакета ради фона.
Размытия нет, потому что `RenderEffect` есть только с Android 12, а рисовать
его руками на старых — отдельная работа не по цене.

Снимок ставится ровно, как его держали: камера пишет пиксели так, как лежала
матрица, а поворот — пометкой EXIF, которую `BitmapFactory` не читает, и
портретное фото ложилось боком. Поворот применяется при сохранении, один раз.
Сразу после выбора открывается кадр — во весь экран, той же матрицей, что
потом под приложением: двумя пальцами ближе и дальше, одним — сдвиг, кнопкой
— поворот на четверть. Снимок в режиме «заполнить» не отъезжает так, чтобы
из-под него показался фон. Кадр хранится рядом с фото, с новым фото
сбрасывается; вернуться к нему — кнопка «Кадр». Своё фото видно и в
предпросмотре темы, а подписи прямо на нём, вне карточек, получают тень
цветом фона темы — на пёстром снимке без неё не читались.

### Язык выбирают, а не угадывают

Первый экран при первом запуске — выбор языка: русский или английский,
двуязычными карточками, с подсказкой от системы. Раньше язык брался у
телефона молча, и человек с турецкими настройками, купивший доступ у
русскоязычного продавца, получал английское приложение без единой ручки,
чтобы это поменять. Ручка есть и в настройках — строка «Язык».

Применяется через `AppCompatDelegate.setApplicationLocales`: на Android 13 и
новее это системная настройка «язык приложения», видная в настройках
телефона; на старых её хранит сам AppCompat, для чего в манифесте объявлена
служба-заглушка `AppLocalesMetadataHolderService`.

### Чужие ключи: VLESS, VMess, Trojan, Shadowsocks, Hysteria2, WireGuard

«+» на экране «Серверы», первый экран и окно на компьютере принимают не
только ключ Marvia, но и то, что выдают другие панели: ссылку одной ноды
(`vless://`, `vmess://`, `trojan://`, `ss://`, `hysteria2://`, `hy2://`,
`wireguard://`), несколько таких столбиком или адрес подписки 3x-ui, Marzban,
Remnawave — список в base64 или текстом, с остатком и сроком из заголовка
`subscription-userinfo`. Нажатая в чате ссылка открывает Marvia, как Happ и
Hiddify; замена стоящего ключа всё равно спрашивается.

Протоколы исполняет Xray-core (`internal/foreign`), тот же, что стоит у
продавцов на другой стороне. Своих реализаций нет: в проекте нет своих
криптопримитивов, и десяток чужих протоколов, написанных заново, принёс бы
ошибки, которых у Xray уже нет. Лицензия Xray — MPL-2.0, как у REALITY, который
проект уже берёт у XTLS; sing-box не взят из-за GPL-3.0, которая
распространилась бы на всё приложение. В сборку идёт только клиентская
сторона нужных протоколов и транспортов — без серверов, API и статистики. Цена
всё равно заметная: ядро на Android выросло примерно на 7 МБ на архитектуру
в сжатом виде, окно на компьютере — с 15 до 34 МБ.

Для приложения чужая подписка — такая же подписка: ноды, замер, автовыбор,
выбор руками, переезд с замолчавшей ноды, остаток и срок. Ноду меряют
настоящим запросом через неё (`generate_204`, как у v2rayNG и Hiddify), а не
открытым портом: заблокированная нода порт открывает. Раз в полминуты
текущую проверяют тем же запросом, две неудачи подряд — переезд на живую.

Чего нет и почему:

- **«Не проверять сертификат»** (`allowInsecure=1`) не выполняется. Xray этот
  ключ убрал, а подключение без проверки — приглашение подменить ноду
  кому угодно на пути. Продавцы с самоподписанным сертификатом дают его
  отпечаток: `pcs` у Xray, `pinSHA256` у Hysteria2 — это клиент понимает.
- **Плагины Shadowsocks** (obfs, v2ray-plugin) — Xray их не исполняет, и
  такая нода отвергается с причиной, а не молча не работает.
- **TUIC, форматы Clash и sing-box** — пока нет.
- **Российский список «мимо туннеля»** даёт только панель Marvia; у чужой
  подписки его нет, под переключателем так и написано. Приложения мимо
  туннеля работают как обычно.

На компьютере весь трафик машины идёт в туннель, и имя ноды, которое Xray
разрешал бы при каждом соединении, ушло бы в тот же туннель — петля. Поэтому
имена всех нод разрешаются заранее, адреса закрепляются в настройках (имя
остаётся в SNI и в Host — за CDN без него не пустят), и мимо туннеля
выводятся адреса **всех** нод подписки. Для VP1 было так же, но выводилась
только текущая нода: после переезда соединения новой пошли бы в туннель —
заодно поправлено. На телефоне этого не нужно: приложение исключено из
своего туннеля, его запросы имён идут обычной сетью.

Проверено на эмуляторе с настоящим сервером VLESS (`go run
internal/foreign/testserver/main.go`, порт пробрасывается `adb reverse tcp:18443
tcp:18443`): ссылка открывает приложение, туннель поднимается, через него идут
запросы имён, TCP и QUIC. Здесь же нашлись две ошибки, которых не видели
тесты пакета, — на обе теперь есть проверки: Xray не создаётся без менеджера
входящих, даже когда входящих нет (тесты подключали серверную часть и
прятали это), и соединение Xray умирало вместе со сроком дозвона, который
мост отменяет сразу после открытия потока.

### Ключ с QR-кода: галерея и камера

Рядом с «Вставить» на экране ключа — «QR»: выбрать в галерее картинку с
QR-кодом, и ключ встанет в поле, как вставленный. Так приходит ключ от
продавца, приславшего его скриншотом. Подходит и `marvia://`, и чужая
ссылка — `vless://`, `trojan://` и остальные из списка выше.

Экран ключа виден только до первого ключа. Вторую подписку с картинки
добавляют в «Серверах»: «Добавить ключ» → «С картинки QR-кода».
Кнопка «Камера» рядом с «QR» открывает сканирование: наведите телефон на
код, показанный на другом экране или напечатанный. В «Серверах» этот способ
доступен через «Добавить ключ» → «Камера». На экране ключа результат
подставляется в поле для проверки и сохранения; в «Серверах» ядро проверяет
ссылку перед добавлением. Отмена сканирования ничего не добавляет.

Разрешение на камеру спрашивается только после нажатия «Камера». При отказе
экран объясняет, что можно вставить ключ или выбрать картинку, и даёт переход
в настройки разрешения. Камера останавливается при сворачивании приложения
и освобождается при закрытии сканера; кадры не сохраняются и не отправляются.

Оба способа распознаёт один ZXing core: чистая Java, без сервисов Google.
Кадры предоставляет CameraX; для галереи разрешение на камеру не нужно —
картинка выбирается системным окном. Крупный чёткий код со
скриншота экрана ZXing сам не находит, поэтому картинку при неудаче
уменьшают в два и в четыре раза и пробуют снова.

### Обновление подписок в фоне

После добавления первого ключа WorkManager сохраняет одно расписание для
всех подписок: период 12 часов с окном выполнения в последние 6 часов.
Открывать приложение для обновления и напоминания о сроке не нужно.
Удаление последнего ключа и «Сбросить всё» отменяют расписание; повторное
открытие приложения не создаёт вторую работу и не откладывает следующую.

Работа ждёт сеть и достаточный заряд, откладывается при включённой экономии
питания и соблюдает ограничения Android. Точное время не гарантируется:
Doze и ограничения производителя могут задержать её дольше 12 часов
([ограничения WorkManager](https://developer.android.com/develop/background-work/background-tasks/persistent/getting-started/define-work)).
При принудительной остановке приложения в настройках фоновые задачи не
выполняются до следующего запуска.

С работающим туннелем запросы всех подписок явно идут через его ядро, включая
разрешение имени панели на ноде, и учитываются в расходе. Отказ туннеля не
переводит запрос на прямую сеть. Без туннеля используется обычный запрос
подписки. Если панель недоступна, остаётся прежний кэш, напоминание считается
по сегодняшней дате, а обновление повторяется позже. Для уведомления нужно
разрешение Android; уже показанное напоминание повторно не приходит.

Разбор синтетических YUV-кадров, расписание и транспорт запросов проверяются
автоматическими тестами. Камера, системное окно разрешения, фактическая
доставка уведомлений и поведение фона на реальном телефоне требуют отдельной
проверки; сборка и тесты её не заменяют.

### Доступ у двух продавцов сразу

На экране «Серверы» сверху есть «+»: подписку берут из буфера обмена или
набирают руками. Ссылку проверяет ядро — то же `ParseAccountLink`, что и на
онбординге, — и только потом она ложится в настройки. Проверка до записи, а
не при подключении: узнать о мусоре через час после того, как его вставили,
значит разбираться вместе с человеком заново.

Подписок много, рабочая одна — как в Hiddify, откуда взят образец. Выбор
ноды в чужой подписке делает её рабочей и поднимает туннель заново: ключ
другой. «Ещё» у провайдера — сделать рабочей или убрать; убрали рабочую —
остаёмся без ключа, а не с чужим втихую.
Имя необязательно: без него берётся домен панели — он и отличает продавцов
друг от друга, а «Подписка 1» и «Подписка 2» не отличают ничего.

Своего ключа у каждой подписки ядру не нужно: ключ покупателя один на весь
список нод, а человек всё равно выходит в интернет через одну страну за раз.
Поэтому смена подписки стоит перезапуска туннеля, а не переделки выбора ноды.
### Настройки: подключение, приложения, журнал

**Подключение и маршруты.** Автозапуск с телефоном, строка в системный
«постоянный VPN» (он же настоящий kill switch — система умеет не пускать
трафик мимо, пока туннель не встал, и прятать это ради своей галочки
нечестно), домашняя сеть мимо туннеля, выбор DNS. Российские подсети мимо
туннеля — на подэкране приложений, рядом с тем, ради чего это нужно. Под
переключателем — правда о списке: сколько подсетей скачано с панели, или
что списка ещё нет. Исключения читаются при поднятии туннеля, поэтому
включённый тумблер действует со следующего подключения — телефон об этом
говорит сразу.

DNS — из четырёх известных: Cloudflare, Google, Quad9, AdGuard — или свой
адрес. Запрос в любом случае уходит внутрь туннеля, это решает ядро; выбор
только в том, чей резолвер стоит на другом конце. Свой адрес проверяется до
сохранения и строго: только IPv4, четыре числа без ведущих нулей, и не из
локальных сетей. Опечатка в адресе резолвера — это «интернет не работает» без
единой подсказки, почему, поэтому причина пишется под полем сразу. Роутер
`192.168.1.1` отвергается отдельной фразой: запрос имени уходит в туннель,
оттуда домашнюю сеть не видно, а нода к частным адресам не ходит вовсе. IPv6
не принимается: при выключенном IPv6 такой резолвер молча перестал бы
отвечать.

**Шифровать запросы имён** — строка под DNS, включена по умолчанию. К
Cloudflare, Google, Quad9 и AdGuard запрос уходит по HTTPS внутри туннеля, и
нода продавца видит только соединение с резолвером. Свой адрес шифровать
нечем — подпись под переключателем так и говорит. Выключенная — открытый DNS
через туннель, как раньше. Подробности — «Запросы имён и нода» ниже.

**IPv6 через туннель** — включён по умолчанию. Выключенный не уходит и мимо:
маршрут `::/0` остаётся в туннеле, ядро отвечает на запросы AAAA «адресов
нет» и закрывает IPv6-соединения сразу, и приложения идут по IPv4 — ровно так,
как это происходит само у ноды без IPv6, только без переезда на «а у этой
есть». Зачем выключать: IPv6-адрес ноды сайты иногда относят к другой стране,
чем IPv4, и один и тот же сервис видит человека то там, то здесь.

**Дробить приветствие** (группа «Маскировка»), выключено по умолчанию. Самая
частая блокировка в России — по имени в TLS-приветствии: фильтр провайдера
читает пакет с ClientHello, находит там SNI и рвёт соединение. Многие такие
фильтры не собирают поток из нескольких пакетов. С включённым дроблением
приветствие уходит тремя TCP-сегментами с паузой в две миллисекунды, и
разрез проходит посреди имени — целиком его нет ни в одном пакете. Сервер
получает те же байты, склеенные TCP, и не замечает разницы: проверено и на
обычном TLS, и на REALITY, который решает, свой ли клиент, как раз по
приветствию.

Место разреза ищется разбором ClientHello, а не угадывается: Chrome
перемешивает расширения, а постквантовый обмен ключами растянул приветствие
почти до двух килобайт, так что имя бывает и в начале, и в самом конце.
Режется TCP, а не TLS-записи: несколько записей вместо одной сильнее против
фильтров, которые TCP собирают, но REALITY читает приветствие одной записью и
разрезанное по записям принял бы за чужое.

Это единственная ручка маскировки на экране, и вот почему именно она: есть ли
у провайдера фильтр по имени, клиент узнать не может, а без такого фильтра
дробление вредно — лишние пакеты, и сама форма «приветствие несколькими
сегментами» тоже примета. Остальные решения маскировки от сети человека не
зависят и приняты внутри.

Для чужих ключей дробление то же самое, а не своё у Xray: там оно режет
кусками случайной длины от начала и либо промахивается мимо имени, либо шлёт
сотню крошечных сегментов. Сырое соединение Xray берёт через подменённый
системный дозвон, а он у Xray один на процесс, — поэтому и выключатель один
на всё. Замер нод на экране «Серверы» идёт с теми же настройками: нода, до
которой доходит только разрезанное приветствие, без дробления показалась бы
мёртвой.

Режется только приветствие по TCP. QUIC у ноды VP1 (`quicFirst`) уходит
целым: там SNI лежит в зашифрованном Initial, который DPI умеет расшифровать,
и разрезать его на уровне TCP нечем. Второе приветствие после
HelloRetryRequest тоже идёт целым: дробится первое, а по нему фильтр и
решает. Наши ноды QUIC по умолчанию не включают.

IPv6, DNS и дробление читаются при подключении; включённый туннель
продолжает работать как был, и телефон говорит, что изменения применятся со
следующего подключения.

Домашняя сеть мимо туннеля — три частных диапазона через `excludeRoute`,
Android 13 и новее, выключено по умолчанию: в чужом Wi-Fi «домашняя сеть» —
чужая, и пускать туда трафик мимо туннеля человек должен сам.

**Приложения.** Три режима. «Мимо туннеля»: отмеченные ходят напрямую —
госуслуги, банки, всё, что не отвечает из-за границы; кнопка «Госуслуги и
банки» отмечает известный набор из установленного. «Только эти»: наоборот, в
туннель идут одни отмеченные — для тех, кому туннель нужен ради двух
приложений, а банк и такси должны видеть настоящий адрес. «Выключено»:
отметки остаются, но не применяются. Режимы исключают друг друга по
устройству Android: `addDisallowedApplication` и `addAllowedApplication` в
одном интерфейсе не сочетаются.

Список полный, а не три системных приложения: с Android 11 чужие пакеты
видны только по объявленному в манифесте `<queries>`, и мы просим ровно то,
что показываем, — приложения с экраном запуска, — а не `QUERY_ALL_PACKAGES`,
за который Play требует объяснений.

**Логи.** Журнал с уровнями — инфо, сбои (нода замолчала, переехали),
ошибки (не поднялся) — и фильтром по ним; «Копировать» берёт видимое,
«Отправить продавцу» — отчёт целиком с моделью телефона. В журнале нет ни
адресов нод, ни ключей: он уходит в чужой чат.

**Дополнительные настройки VPN** открываются своим экраном, без цепочки
системных окон. Размер пакета (MTU) можно сменить на 1280, 1400 или 1500:
меньший помогает, если отдельные сайты загружаются лишь частично. Тип сети
«По сети» наследует лимитность Wi-Fi или мобильной связи; «Всегда» помечает
VPN лимитным, чтобы приложения могли отложить крупные загрузки. Эта строка
есть на Android 10 и новее, где система умеет менять признак VPN. Для ключей
Marvia можно выключить отправку результатов замеров нод панели продавца —
выбор ноды на телефоне продолжит работать. Эти три параметра вступают в силу
при следующем подключении. Интервалы обновления с включённым и погашенным
экраном и проверки отклика меняются без переподключения на следующем цикле;
три готовых режима задают их
вместе, а каждый интервал можно затем поправить отдельно. Выключение
повторного замера отклика для экрана не выключает надзор за самой нодой.
Краткий вид обязательного уведомления скрывает ноду и скорость, но оставляет
статус подключения; в этом режиме служба не перерисовывает уведомление на
каждом изменении скорости.

«Сбросить всё» выключает туннель, стирает подписки с кэшем, тему с фоном и
значком, настройки и учёт, и начинает с первого экрана.

Из макета намеренно нет: переподключения при смене сети (надзор делает это
сам), выбора транспорта и выхода DNS из туннеля (решает ядро), уведомлений по
отдельности, переноса настроек — за такими строками пока нет действия.

### Диагностика

Первая строка группы «Диагностика и приложение» в настройках. То же, что
раздел «Диагностика» в окне на компьютере, — шаги, коды и пороги те же, и
решает их ядро (`mobile/diag.go`), а не Kotlin.

**Где ты в интернете.** Страна с флагом, адрес и сервер. Адрес и страна —
ответ `www.cloudflare.com/cdn-cgi/trace`, полученный через ядро туннеля: само
приложение из своего VPN исключено, и обычный запрос из него показал бы
настоящий адрес телефона. Это адрес выхода ноды; запоминается до смены ноды.

**Качество связи.** Отклик (медиана последних ответов), джиттер и потери —
из пингов текущей ноды: тех, что служба делает по расписанию, и одного раз в
пять секунд, пока экран открыт. После переезда на другую ноду замеры
начинаются заново. Ниже — как именно подключено, только то, с чем
дозванивается ядро: протокол (VP1 или протокол чужой ссылки), транспорт
(TLS, REALITY, WS, QUIC; у чужих — транспорт и защита Xray), имя прикрытия
и сколько запасных у REALITY, отпечаток TLS. Без туннеля — «нужно
подключение».

**Проверить всё.** Семь шагов по порядку, каждый появляется, как только
ответил: интернет без VPN (TCP до 1.1.1.1 и 8.8.8.8 без данных), запросы
имён (с туннелем — к резолверу из настроек тем же путём, что у приложений:
по HTTPS или открытым DNS через туннель; без туннеля — резолвером телефона),
отвечают ли серверы по TCP (до шести, текущий первым; без туннеля — из кэша
подписки, без похода в панель; ноды Hysteria2 и WireGuard по TCP не стучатся
— у них UDP), подключение, адрес через туннель, «адрес не утекает» и восемь
главных сайтов через туннель (Google, YouTube, Telegram, WhatsApp, Instagram,
ChatGPT, X, GitHub; любой HTTP-ответ — «открылся»). Шаги, которым нужен
туннель, без него — пропуск с пометкой «нужно подключение», а не беда.

«Адрес не утекает» на телефоне устроен наоборот, чем на компьютере. Там
обычная программа обязана ходить через туннель. Здесь обычный путь самого
приложения — мимо туннеля, то есть настоящий адрес телефона, а сайты видят
адрес выхода ноды. Совпали — сайты видят настоящий адрес (выход ноды в той
же сети, что телефон), и предлагается другой сервер. Не удалось сравнить —
«Переподключиться». Ни один из двух адресов шаг не возвращает: сравнение идёт
в ядре.

Двух шагов окна здесь нет. «Браузер идёт через туннель» проверял бы путь
обычной программы через адаптер, а у приложения, исключённого из своего VPN,
такого пути нет. «Помехи рядом» искал бы второй VPN и прокси: второй VPN
Android сам не пускает — он забирает интерфейс, и наш туннель выключается, —
а прокси туннелю на телефоне не мешает.

У плохого шага — кнопки с настоящим действием: «Подключиться»,
«Переподключиться» (служба поднимается заново, после того как прежняя
разрушилась), «Сменить сервер» (ведёт на «Серверы»), «Включить дробление»
(включает настройку и переподключает) и «Сменить DNS» (выбор резолвера из
настроек). Где помочь нечем — нет интернета вовсе или сервер один, — кнопки
нет. Ядро отдаёт коды и числа, слова — в ресурсах приложения на русском и
английском; тест ядра сверяет, что у каждого кода есть строки в обоих
словарях и обработчик кнопки.

**Скорость.** «Замерить» качает через туннель до 30 МБ с
`speed.cloudflare.com`, не дольше пяти секунд, — из трафика подписки и с
учётом в расходе сессии, поэтому только по кнопке и только с туннелем.
Последние пять замеров с временем и сервером лежат в настройках приложения;
«Сбросить всё» стирает и их.

**Скопировать отчёт продавцу.** То, что на экране, словами интерфейса, и
ниже — тот же отчёт, что «Отправить продавцу» в журнале. Адреса выхода в нём
нет, только страна; весь текст проходит `internal/redact`, который закрывает
любые адреса и ключи ссылок.

Ушёл с экрана — всё, что ещё шло, обрывается: замер скорости не докачивает
мегабайты в пустоту.

### Расход считает сам телефон

Вкладка «Расход» — из макета: кольцо из сегментов по дню периода, где
читается яркость, а не форма, с итогом и средним внутри; пик, лимит подписки
и дни в периоде; плавная линия по дням; доли стран полосой с флагами; неделя
по часам клетками. Период — неделя или тридцать дней. Всё считает
приложение, и цифры не уходят с телефона.

Иначе было нельзя. У панели на каждого человека есть только накопительный
итог, и по нему не ответить ни на «сколько вчера», ни на «в какие часы»;
завести у неё подённую историю каждого покупателя — значит знать о людях
больше, чем нужно для выдачи доступа. Поэтому считает тот, кого это
касается.

Байты считает обёртка `tunbridge.Metered` вокруг дозвона — та же, что
показывает скорость в окне на компьютере. Считаем поток до цели, а не
соединение с нодой: в цифру не попадают ни добивка, ни служебные кадры, ни
переподключения. Человеку показывается то, что он скачал, а не то, за что
владелец ноды платит хостеру, — это нода считает отдельно и по-другому.

Служба снимает счётчик раз в две секунды при включённом экране и раз в
десять при погашенном и кладёт разницу в текущий час; хранится тридцать
суток по 24 числа в настройках приложения. Книга учёта живёт в памяти, одна
на процесс, а на диск уходит раз в минуту, при смене часа и при остановке
туннеля: раньше каждое снятие переписывало файл настроек целиком — полсотни
записей в минуту на флеш ради пары килобайт разницы. Выгрузка процесса
системой стоит не больше минуты учёта. Сутки — по
местному времени телефона, а не по UTC, как у панели: там выбор между
поясами продавца и покупателя, а здесь пояс один, и «вчера» должно
совпадать с человеческим вчера.

Подпись под диаграммами говорит прямо: это расход одного телефона. Другое
устройство с тем же ключом считает своё, и сложить их неоткуда — по той же
причине, по которой панель не ведёт эту историю.

### Ошибка говорит покупателю, что делать

Ядро формулирует точно: `dial tcp: lookup panel.example: no such host`. Для
разбора это незаменимо, для покупателя — пустой звук. Он заплатил за интернет
и хочет знать, на что нажать.

Поэтому ядро сообщает вместе с подробностями ещё и **вид неудачи** —
`account`, `panel`, `nodes` или `system`, — а фразу под него подбирает
приложение:

```
Не подключилось
Не получается получить список серверов. Проверьте, есть ли интернет
dial tcp: lookup panel.example.invalid: no such host      ← мелким, копируется
```

Разделение именно такое, а не «пусть ядро сразу пишет по-человечески», по двум
причинам. Русский текст интерфейса расползся бы по ядру, а нужен будет ещё на
фарси и на китайском — это те же страны, ради которых всё затевалось. И точный
текст никуда не девается: покупатель снимет экран целиком и пришлёт продавцу,
а тому нужна как раз нижняя строка. Поэтому её можно выделить и скопировать.

Вид едет первой строкой сообщения об ошибке. Не от хорошей жизни: наружу
gomobile отдаёт обычное исключение, и приложить к нему что-то, кроме текста,
некуда. Зато вид проставляется там же, где случилась неудача, а не угадывается
потом разбором текста — переформулируешь сообщение, и угадывание сломается
молча.

`TestConnectNamesFailureKind` следит, что вид действительно доезжает. Проверка
выглядит мелкой, но держит важное: перестанет проставляться вид — покупатель
увидит невнятное вместо «ключ не подошёл», и узнаем мы об этом от него.

### Дескриптор интерфейса принадлежит ядру

`VpnService` выдаёт дескриптор, а закрывает его gvisor. Значит владелец должен
быть один, и это Go: Kotlin отдаёт дескриптор через `detachFd` и больше к нему
не прикасается, а ядро закрывает его и при неудачном запуске, и при остановке.

Иначе вышло бы двойное закрытие. На Linux это не безобидная ошибка на пустом
месте: номер уже освободился, его занял другой сокет, и вторым закрытием мы
рвём чужое соединение — в случайном месте и без единой строчки в журнале.

### IPv6 заворачивается в туннель, даже когда у ноды его нет

Соблазн велик: не объявлять маршрут `::/0` и не связываться. Но тогда весь
трафик IPv6 пойдёт мимо туннеля, то есть цензор увидит ровно ту часть, которую
мы прячем. Пусть лучше соединение не состоится внутри туннеля: приложения
после этого сами переходят на IPv4.

Но не за счёт человека. На живой ноде без IPv6 это было 700 отказов из 835
за два часа, и журнал телефона состоял из «цель недоступна» целиком. Теперь
ядро, узнав, что у ноды IPv6 нет (код `0x04` или три отказа подряд), само
отвечает на AAAA «адресов нет» — приложения берут IPv4 с первого раза, — а
IPv6-соединения из кэша закрывает, не беспокоя ноду. Отказы по отдельным
сайтам в журнал и на экран больше не попадают вовсе: это не беда туннеля, и
показывать их значит пугать зря. Беда туннеля — нода молчит — видна как
раньше.

### Кнопка в шторке и уведомление

Туннель включают чаще, чем открывают приложение, поэтому в шторке есть
плитка Marvia: нажал — включилось, нажал ещё — выключилось, под именем —
страна или «Отключено». Нет ключа или система ещё не давала разрешения на
VPN — плитка открывает приложение: спросить разрешение умеет только экран.

Уведомление работающего туннеля — страна, скорость вниз и вверх, отклик и
часы сессии, знак в цвет темы. Скорость пересчитывается раз в две секунды,
отклик — по интервалу из настроек, оценкой ядра по соединению с нодой (см.
«Отклик ноды и время подключения»); то же число стоит и на главной. Часы
ведёт система, и перерисовывать уведомление каждую секунду ради них не нужно.

Когда у телефона нет сети совсем — ни Wi-Fi, ни мобильного интернета, — в
уведомлении вместо «Подключено» стоит «Нет сети» и что туннель продолжит
сам, а на главной под состоянием — та же причина. Раньше там держалось
«Подключено» с нулевой скоростью, и человек искал поломку в VPN. Сеть,
которую Android не смог проверить своим запросом к Google, сетью считается:
в сетях, где этот адрес режут, исправный интернет иначе выглядел бы
пропавшим.

### Российский список качает ядро

Список подсетей «мимо туннеля» раньше качало приложение своим HTTP по имени
панели. Там, где имя не разрешалось, список не приходил никогда, и под
переключателем навсегда оставалось «панель была недоступна», а российские
сайты шли через ноду за границей и не открывались. Теперь его качает ядро,
тем же путём, что подписку, — с адресами панели из ссылки; пробует при
каждом открытии приложения, пока список не скачан, и после подключения; а
под переключателем пишет настоящую причину, если не вышло.

### Свой трафик в свой туннель не заворачиваем

`addDisallowedApplication` на собственный пакет. Без этого соединение до ноды
пошло бы через интерфейс, который сам же к этой ноде и ведёт.

### Запросы имён уходят в туннель

Ядро перехватывает любой UDP на порт 53 — неважно, какой адрес приложение себе
прописало. Запрос имени, ушедший мимо туннеля, выдаёт цензору весь список
посещённых сайтов, даже когда сам трафик он расшифровать не может.

### Запросы имён и нода

Туннель прячет имена от провайдера, но не от ноды: она расшифровывает VP1, и
открытый запрос к `1.1.1.1:53` уходит от неё в интернет таким, каким его
написало приложение. Продавцу, у которого стоит нода, хватило бы `tcpdump`,
чтобы видеть каждое имя, которое спрашивает покупатель. Так было до
0.13.0-alpha.3: запрос шёл через ноду открытой датаграммой, а у ноды без
датаграмм — открытым DNS по TCP.

Теперь по умолчанию ядро отвечает на запросы имён само
(`internal/securedns`): к выбранному резолверу запрос уходит по
**DNS-over-HTTPS** (RFC 8484) через туннель. Нода видит TLS-соединение с
`1.1.1.1:443` и имя `cloudflare-dns.com` в его приветствии — кому, когда и
сколько байт, — но не имена внутри. Запросы добиты до кратного 128 байтам
(RFC 8467), чтобы длина записи не выдавала длину имени. Перехватывается и UDP,
и TCP на порт 53: открытого запроса к ноде не уходит ни одного, какой бы адрес
ни прописало приложение.

Почему DoH, а не DNS-over-TLS. Внутри туннеля цензор не видит ни того, ни
другого. DoT ходит на свой порт 853, и нода по номеру порта знает, что это
имена; ещё ему нужна своя сборка потока — очередь запросов, сопоставление по
ID, переподключения. DoH ходит на 443, а HTTP/2 из стандартной библиотеки сам
держит одно соединение на много запросов. TLS и проверку сертификата делает
`crypto/tls` против системного хранилища — своей криптографии здесь нет.

Резолверы — те же четыре: Cloudflare, Google, Quad9, AdGuard, у каждого по
два адреса. Адреса зашиты, а не спрашиваются: спросить адрес резолвера, кроме
как у резолвера, не у кого.

- **Таймауты и запасной резолвер.** На один адрес — три секунды, на вопрос
  целиком — десять. Не ответил выбранный — второй адрес той же службы, потом
  остальные три службы. Следующие вопросы идут сразу к ответившему, без
  повторного таймаута; к выбранному ядро возвращается через две минуты.
  Человек, выбравший AdGuard ради фильтра рекламы, на это время получит
  ответы без фильтра — остаться без имён, то есть без интернета, хуже.
- **Отказ всех резолверов — ошибка, а не откат на открытый DNS.** Нода,
  которая хочет видеть имена, может просто перестать пропускать соединения к
  резолверам или подменить сертификат, и тихий откат отдал бы ей ровно то,
  что мы прячем. Человек видит ошибку «ни один резолвер не ответил» и сам
  решает, выключить ли шифрование.
- **Кэш.** Ответ хранится не дольше наименьшего TTL его записей и не дольше
  часа; «такого имени нет» без срока от резолвера — полминуты. Из кэша ответ
  отдаётся с TTL, уменьшенным на прошедшее время. При переезде на другую ноду
  кэш и соединения сбрасываются: резолвер видит адрес ноды и подбирает адреса
  CDN рядом с ней.
- **Большой ответ.** Не влезающий в датаграмму приложения ответ уходит пустым
  с флагом TC, приложение переспрашивает по TCP, и ядро отвечает целиком.
- **Российские сайты мимо туннеля** резолвятся как раньше: имена у них
  спрашиваются у того же резолвера через туннель, а мимо туннеля идёт только
  само соединение — по адресу. Резолвер и раньше видел адрес ноды, а не
  телефона, так что ответы для них не меняются.

Чего шифрование имён **не** прячет. Нода видит адреса сайтов, к которым
идут соединения, и имя сайта в TLS-приветствии (SNI) — его шифрует только
ECH, а его поддерживают немногие сайты. Обычный HTTP нода видит целиком.
Шифрование имён убирает из рук продавца готовый журнал всех имён, но не
делает ноду слепой.

Остаются открытыми, как раньше:

- выключенный переключатель «Шифровать запросы имён»;
- свой адрес резолвера — как с ним говорить по HTTPS, мы не знаем;
- клиент SOCKS (`marvia-client`): в режиме `socks5h` имя сайта уходит ноде
  адресом назначения, так устроен сам SOCKS.

С чужой подпиской (VLESS, Trojan и прочие) шифрование имён работает так же:
мосту всё равно, через какой протокол идёт поток до резолвера.

Свой стек TCP мы при этом не пишем: Android даёт сырые IP-пакеты, а туннелю
нужны соединения. Берём проверенный gvisor через `tun2socks` — по той же
причине, по которой не писали свой TLS.

### Сборка, версия и подпись

**Обычный путь — сборка выпуска на GitHub.** Метка `v*` собирает ядро и
приложение и кладёт в черновик выпуска `marvia-android.apk` (его установщик
кладёт продавцу в `dist`) и `marvia-android.aab` (для Google Play, тот
принимает только bundle). Оба входят в `SHA256SUMS`, подписанный GitHub, —
то есть происхождение APK проверяется так же, как у панели и ноды. Сборка
сверяет сертификат с отпечатком `53:EB:…:7E:82`: чужой ключ выпуск не
соберёт.

Ключ для этого лежит в секретах окружения `release`
(`ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`,
`ANDROID_KEY_PASSWORD`). Окружение пускает к ним только сборку по метке
`v*`: ветка, чужой PR и ручной запуск их не видят. Секретов нет — выпуск
собирается без APK, как раньше.

**Запасной путь — со своего ПК**, тем же ключом с диска:

```powershell
.\scripts\publish-apk.ps1 -Tag v0.13.0-alpha.2
```

Руками — `cd android && ./gradlew assembleRelease bundleRelease`, пакеты в
`android/app/build/outputs/`.

**Номер версии — из метки, код обновления — из `android/version-code`.**
Метка уходит в `MARVIA_VERSION`, gradle берёт из неё `versionName`. Код
телефон сравнивает при установке поверх и ставит только больший; после
снятых 1.0 и 1.0.1 (коды 10000 и 10001) коды идут с 10002, и из номера
alpha их не вывести. Поэтому код лежит файлом, его читают и сборка на
GitHub, и скрипт, и **перед каждой новой меткой его увеличивают на единицу**.
Использованные коды: 10002–10005 (10005 — `0.13.0-alpha.1`). Та же строка номера версии
лежит на панели файлом `.version` рядом с apk — по ней приложение узнаёт,
что устарело. Без переменной сборка называется `dev` с кодом 1 и обновлений
не ждёт.

Ключ подписи лежит **вне репозитория**: путь берётся из `MARVIA_RELEASE_KEYS`
— одной переменной для gradle, скрипта и этого текста, — по умолчанию
`veil-keys/veil-release.properties` рядом с каталогом проекта: сам ключ при
переименовании не менялся и не мог. Файла нет — сборка выйдет неподписанной
и честно об этом скажет, а не подпишется молча отладочным ключом.

**В Play — тот же ключ.** Play App Signing предлагает завести свой; тогда
приложение из Play и apk с панели подписаны разным, и телефон считает их
разными программами — перейти с одного на другое без переустановки нельзя.
При первой загрузке в консоль Play выбирают «использовать свой ключ» и
загружают наш.

**Подпись — это личность приложения на всю жизнь.** Телефон принимает
обновление только за той же подписью, что и установленная версия. Потеряешь
ключ — обновить приложение у покупателей будет нечем, придётся просить каждого
удалить старое и поставить новое. Утечёт — кто угодно выпустит «обновление» от
твоего имени, и телефоны его примут.

Включены схемы подписи v2 и v3. v3 нужна ради одного: она единственная
позволяет однажды сменить ключ, не теряя установленные приложения, — а ключ
живёт тридцать лет, и за это время всякое бывает. v1 не нужна, это подпись для
Android 6 и старше.

**Сжатие кода намеренно выключено.** Выигрыш почти нулевой: из четырнадцати
мегабайт пакета тринадцать — ядро на Go, скомпилированное в машинный код, до
которого R8 не дотягивается вовсе. А риск настоящий: классы моста вызываются
через JNI, статический анализ обращений к ним не видит и выбрасывает их как
ненужные. Правила в `proguard-rules.pro` это чинят, но ошибка в них проявляется
не на сборке, а падением уже у покупателя.

### Google Play

Подписанный AAB уже прикладывается к релизу, но приложение пока не опубликовано
в Play. Текущий порядок подготовки, проверки сертификата, заполнения Data
safety, деклараций VPN и фоновой службы, тестового доступа и закрытого теста —
в [отдельной инструкции](google-play.md). Не переносите старую формулировку
«данные не собираются» в анкету: приложение обменивается данными с панелью и
нодой, а для определения страны выхода иногда обращается к `ipapi.co` через
туннель. [Политика конфиденциальности](privacy.md) описывает этот обмен.

Скриншоты снимает `scripts/play-shots.ps1` с эмулятора «marvia»
(`scripts/android.ps1 -Emulator`) в `dist/play-shots`, 1080×2400. Перед
съёмкой используйте отдельный тестовый ключ без данных покупателей.

### Что проверено на живом телефоне

Samsung Galaxy A51, Android 13, arm64:

- приложение ставится и запускается, экран рисуется, отступы под вырез камеры
  и панель навигации считаются верно, клавиатура не закрывает кнопку;
- вызов в ядро работает: неверная ссылка отвергается, и на экран приходит
  текст ошибки, написанный в Go, — «ожидалась схема marvia://»;
- система принимает нашу службу как VPN: показывает своё окно согласия и
  переключает на нас активный VPN;
- при неудаче служба честно останавливается и не остаётся висеть в памяти;
- фразы под виды неудач доходят до экрана. Испорченный ключ даёт «Ключ доступа
  не подошёл. Возьми новый у продавца», недостижимая панель — «Не получается
  получить список серверов. Проверь, есть ли интернет», и под каждой мелким
  стоит точный текст из ядра.

Первый же запуск нашёл ошибку, которую сборка показать не могла: **причина
обрыва пропадала с экрана.** `shutdown` записывал её, следом `stopSelf` звал
`onDestroy`, а тот останавливался ещё раз и объявлял обычное «отключено»
поверх причины. Человек видел, что не работает, и не видел почему — худший
вид ошибки именно в такой программе. Теперь остановка происходит один раз, и
причина доходит до экрана целиком — проверено на том же телефоне:

```
Не подключилось
список нод: запрос подписки: Get "https://panel.example.invalid/sub/proverka
?format=json": dial tcp: lookup panel.example.invalid: no such host
```

**Отладка по Wi-Fi для этого не годится.** Как только туннель поднимается,
трафик `adbd` уходит в него вместе со всем остальным, и связь с телефоном
рвётся на середине проверки. Проверять надо по проводу.

### Туннель с телефона до интернета

Проверено на живой ноде: сервер в Фуджейре, телефон в России, между ними
REALITY под `www.samsung.com`.

```
Instagram   200 за 1,98 с
YouTube     200 за 1,17 с
Discord     200 за 0,74 с
ipinfo.io   <адрес ноды>, Fujairah, AE
```

Панель списала с подписчика 20 МБ — учёт считает то же, что реально прошло.
На телефоне поднялся `tun0` с обоими адресами, IPv4 и IPv6, значок VPN в
строке состояния, на экране «Подключено. Нода: ae-1».

Зонд цензора при этом видит настоящий сайт. С машины в России, откуда шла
проверка, параметры рукопожатия ноды и подлинного `www.samsung.com` совпали
полностью:

```
                      наша нода            настоящий сайт
протокол              TLSv1.3              TLSv1.3
шифр                  AES_256_GCM_SHA384   AES_256_GCM_SHA384
ключ сервера          2048 бит             2048 бит
ALPN                  h2                   h2
проверка сертификата  0 (ok)               0 (ok)
```

Через ноду `curl` получает `301` и подлинный сертификат DigiCert, выданный
Samsung SDS. Проверялось и на TLS 1.2, и на 1.1 — нода ведёт себя как сайт на
каждой версии, включая отказ там, где отказывает сайт.

**Про обрывы соединений человеку не сообщается.** Отличить «приложение само
закрыло соединение на полуслове» от «нода умерла посреди передачи» на уровне
моста невозможно: адаптер gvisor делает `errors.New(err.String())` и
выбрасывает тип, оставляя голый текст. Сообщение, которое не различает эти
случаи, хуже молчания — оно приписывает `endpoint is closed for send` к
совершенно здоровому туннелю каждый раз, когда человек листает ленту и
обрывает загрузку. Сигнал при этом не теряется: если нода умерла, следующее
соединение не откроется, а об этом сообщается.

**Порт 8444 — временный.** Нода стоит не на 443 только потому, что на том
сервере :443 занят посторонним сайтом. В бою так нельзя: корпоративные и
гостиничные сети режут исходящие на нестандартные порты, да и TLS на 8444 сам
по себе примета — настоящие сайты там не живут.

### Чего ещё нет

- ручек протокола — MTU, «только TCP», отключение маскировки — намеренно,
  см. вкладку «Ещё»; единственное исключение — дробление приветствия, оно
  зависит от сети человека, а не от ноды.

## Установка панели

Сначала заведи домен и нацель его A-записью на этот сервер — без этого
установщик остановится на первом шаге и правильно сделает.

```bash
curl -fsSL https://github.com/jytt8u/marvia/releases/latest/download/install-panel.sh -o install-panel.sh
sh install-panel.sh --domain panel.example.com
```

Компилятор не нужен. Скрипт сам определяет разрядность сервера, скачивает
ядро, сверяет контрольную сумму, ставит службу и **получает сертификат Let's
Encrypt**. В конце печатает админский токен — один раз, отдельным блоком.

Дальше добавление нод идёт готовыми командами: бинарники панель раздаёт им
сама из своего каталога `dist`, и скачивать для ноды ничего не надо.

Если на том же сервере будет стоять нода, она займёт 443 — тогда панели нужен
другой порт: `--port 8443`. Адрес подписки понесёт порт вместе с собой, клиент
это умеет.

### Откуда берётся ядро

Исходники и сборки лежат в одном репозитории — `jytt8u/marvia`. Раньше их было
два: код закрыт, бинарники открыты. Так делать перестали, потому что закрытый
код в проекте про обход блокировок вызывает подозрение раньше любого другого
вопроса, а стойкость у нас и так не зависит от секретности реализации — своих
криптопримитивов в проекте нет.

Сборку делает `.github/workflows/release.yml` на метку вида `v0.1.0`: гоняет
тесты, собирает под `linux/amd64` и `linux/arm64`, считает `SHA256SUMS` и
сохраняет черновик релиза. Публикация 1.x заблокирована до проверки;
автоматической публичной выкладки сейчас нет. Чужой токен для этого больше не нужен: `GITHUB_TOKEN`
действует ровно на тот репозиторий, где идёт сборка.

Можно указать иначе:

| Ключ | Когда нужен |
|---|---|
| `--from https://…/marvia_linux_amd64.tar.gz` | своё зеркало |
| `--bin-dir /путь` | бинарники уже распакованы или собраны руками |

**Контрольная сумма сверяется, когда рядом с архивом лежит `SHA256SUMS`.**
Подменённый архив, распакованный на сервере с правами root, — это не
неудобство, а чужой доступ ко всем покупателям. Если сверить не с чем,
установщик скажет об этом вслух и продолжит.

**Если с сервера не открывается github.com** — так бывает у хостеров в Иране и
Китае — скачай архив на машину, с которой открывается, положи рядом со
скриптом и запусти с `--bin-dir`: бинарники рядом с собой установщик найдёт
сам.

### Какая версия стоит

Версия впечатывается в бинарник при сборке. Спросить можно у каждого:

```bash
marvia-panel -version
```

Панель пишет её и первой строкой в журнал (`journalctl -u marvia-panel`) — в
обращения в поддержку обычно попадает именно журнал.

По сети версия отдаётся **только с авторизацией**:

```bash
curl https://panel.example.com/api/v1/version -H "Authorization: Bearer $MARVIA_ADMIN_TOKEN"
```

В открытом `/healthz` её нет намеренно: точная версия говорит сканеру, какие
дыры пробовать, и заодно опознаёт панель как нашу — а домен панели и так самое
уязвимое место платформы. Сборка не из релиза честно отвечает `dev`.

### Панель за Cloudflare

Домен панели — самое уязвимое место платформы: к нему ходят все покупатели
одного продавца, и блокировка адреса сервера обрывает не одну ноду, а всё
сразу. Cloudflare это чинит: покупатели ходят на его адреса, а не на сервер.

Что важно знать, если включаешь.

**Панель выясняет свои адреса один раз, при запуске.** Они уезжают в ссылки
доступа подсказкой `?ip=`, чтобы клиент не спрашивал домен у резолвера
провайдера. Значит после включения Cloudflare панель надо перезапустить —
иначе в свежих ссылках останется прямой адрес сервера, и они переживут
блокировку ровно так же плохо, как и раньше. Что попало в ссылки, панель
говорит при запуске:

```
ссылки доступа подсказывают адреса панели: 203.0.113.10, 203.0.113.11
```

Клиент перебирает подсказанные адреса по очереди. Адрес, который не ответил
или принял соединение и тут же его оборвал (так ведут себя и мёртвый узел
CDN, и фильтр провайдера), пропускается; не ответил ни один — клиент
спрашивает домен как обычно.

**Порт.** Cloudflare проксирует https не на любом порту; `8443`, на котором
панель стоит по умолчанию, в список входит.

**Сертификат продолжает получать сама панель.** Проверка Let's Encrypt идёт по
`:80`, и Cloudflare пропускает `/.well-known/acme-challenge/` до сервера —
проверено запросом снаружи: отвечает панель, а не Cloudflare. Перекладывать
сертификат на Origin CA не обязательно.

**Адрес сервера всё равно виден** — он стоит в ссылках на ноду, если нода живёт
на той же машине. Cloudflare прячет не сервер, а панель: заблокированный адрес
унесёт ноду, но покупатели по-прежнему получат список нод и переедут на живую.

### Сертификат панель получает сама

Раньше она отдавала голый HTTP и требовала обратный прокси. Логика была
разумная: сертификатами занимается nginx, панель занимается своим делом. На
практике это значило, что продавец, поднявший панель на отдельной машине,
обязан ради одной подписки освоить ещё и nginx с расписанием обновления.

Теперь `-acme-domain` — и сертификат берётся при первом обращении и
продлевается сам. Обратный прокси никуда не делся и остаётся правильным
выбором там, где он уже стоит: `-tls-cert` и `-tls-key` работают как прежде.

Хранилище сертификатов обязано переживать перезапуск, и установщик кладёт его
в `/opt/marvia/acme`. Без постоянного хранилища каждый рестарт заказывал бы новый
сертификат, а у Let's Encrypt на домен всего пять штук в неделю: после пятого
перезапуска панель осталась бы без сертификата на неделю — а вместе с ней все
покупатели без обновления списка нод.

**Владение доменом проверяется по 80-му порту.** Второй способ, через TLS на
443-м, здесь не работает: этот порт обычно занят нодой, а нода на незнакомого
гостя отвечает сайтом прикрытия — проверка ушла бы в Samsung и не вернулась.

### Журнал событий

Каждый вход в панель пишется в журнал: кем (админ или имя ключа), из
какого браузера и с какого адреса. Перезагрузка страницы входом не
считается. Чужой вход по утёкшему токену видно здесь.

**Помощник «только смотреть».** «Ключи ботов» → ключ с одним правом
`read`. Войдя им, помощник видит клиентов, ноды и статистику, но кнопок,
которые что-то меняют, у него нет, а сервер такие запросы отклоняет.

Отвечает на один вопрос: что делали с панелью. Завели человека, продлили,
отключили, сменили ключ, добавили ноду, выпустили ключ боту. Без него спор
«я платил» — слово против слова, а «куда делась нода» — догадки.

Смотреть: **Журнал**. Или запросом, админским токеном:

```bash
curl https://panel.example.com/api/v1/events?limit=200 \
  -H "Authorization: Bearer $MARVIA_ADMIN"
```

Видно, **кто** сделал: `admin` — это тот, кто вошёл админским токеном, а бот
записывается именем своего ключа. Если ключей несколько, сразу понятно, чей
бот наделал дел.

**Чем он намеренно не является.** Это не слежка за людьми. Здесь нет ни
адресов, ни того, кто когда подключался, ни тем более куда ходил: подключения
видит нода, и она про них ничего не пишет. Записываются только действия
владельца панели над своей же панелью.

**Секретов в журнале нет.** Смена ключа доступа записывается как факт, сам
ключ туда не попадает; выпуск ключа боту — имя и права, не токен. Журнал
смотрят с экрана и пересылают, и секрет, попавший туда однажды, дальше живёт
своей жизнью.

**Удалили человека — исчезли и записи о нём.** Записи привязаны к покупателю
внешним ключом с каскадом, и это нарочно: журнал, переживающий удаление,
превратил бы «удалили значит удалили» в неправду.

Хранится 90 дней. Спор об оплате случается в пределах нескольких недель, а
дальше запись становится не доказательством, а грузом, который жалко потерять
и опасно хранить. Старое панель вычищает при запуске.
### Оповещения в телеграм

Поломку замечают последней: нода молчит третий час, подходит срок, копия базы
не снялась неделю назад. Без оповещений всё это обнаруживается тогда, когда
уже мешает, — а часто и позже.

Панель шлёт их сама, в телеграм-бот владельца панели: **Оповещения** →
включить, вписать токен бота у `@BotFather` и `chat_id` (его скажет
`@userinfobot`). Тому, кто держит панель для себя и пары знакомых, это ровно
так же полезно: бот заводится за минуту и молчит, пока всё хорошо.

О чём говорит:

| Повод | Когда |
|---|---|
| Нода замолчала | не отмечалась больше часа. Панель считает ноду живой, если та была на связи последние десять минут, — порог выше нарочно, чтобы перезапуск и минута плохой связи не будили ночью |
| Нода вернулась | отметилась снова |
| Кончается срок | у скольких-то человек осталось меньше трёх дней |
| Копия базы не снялась | и отдельно — когда снова стала сниматься |

Про одну и ту же беду говорится **один раз**: оповещение, которое повторяется
каждые пять минут, перестают читать, а вместе с ним перестают читать и важные.
О чём уже сказано, панель помнит в памяти — после перезапуска про всё ещё
молчащую ноду скажет ещё раз.

**В сообщениях нет имён.** «У троих кончается срок», а не «у Артёма, Нины и
Дмитрия». Переписка с ботом живёт в телеграме и переживёт и панель, и того,
кто её держит; превращать её в список людей незачем. На вопрос «надо ли идти
смотреть» число отвечает не хуже, а кто именно — видно в панели.

**Токен бота панель обратно не показывает.** Он хранится у неё, а в API уходит
только признак «задан»: показать его — значит положить секрет в историю
браузера. Чтобы сменить, впиши новый; пустое поле означает «оставить прежний».
Выключение оповещений стирает токен из базы.

**Чем платим.** Включённые оповещения означают, что панель ходит наружу, на
`api.telegram.org`. Её адрес становится известен телеграму и виден тому, кто
смотрит на трафик сервера. Поэтому по умолчанию они выключены, и пока их не
включили, панель наружу сама не ходит. Единственное исключение — страница
«Обновления»: открытая продавцом, она спрашивает у `github.com` номер
последнего релиза — в тестовом канале не чаще раза в двадцать минут, в
стабильном раз в час, по кнопке «Проверить сейчас» сразу, — и ночное
автообновление, если его включили (см. «Обновление кнопкой»).

### Главная: сроки, ноды, тарифы

Все разделы видны в меню сразу, тремя группами: «Продажи» (панель, клиенты,
ключи ботов), «Сеть» (ноды, статистика) и «Настройки» (оповещения, журнал,
обновления, вид). Окно уже 1100 точек сжимает меню до значков с подсказками,
на телефоне оно открывается кнопкой в шапке. Главная отвечает на вопросы
продавца:

- **Показатели** — активные ключи, трафик за 30 дней, ноды на связи и
  сколько истекает в ближайшую неделю. У трафика — сравнение последних семи
  дней с семью перед ними, если было с чем сравнивать.
- **График трафика** за 30 дней, все дни подряд, с нулями; наведение
  показывает день и объём. В «Статистике» те же дни столбиками: скачанное и
  отданное отдельно.
- **Расход по нодам** — сколько провезла каждая и какая доля от всех; не
  отвечающая нода — оранжевым. Рядом с нодой — флаг её страны по тому же
  словарю, что в подписке; где система флагов не рисует (Windows), вместо
  него код страны.
- **Скоро кончается срок** — у кого срок кончится в ближайшую неделю или
  кончился за последнюю, с тарифом и кнопкой **Продлить** прямо в строке.
  С тарифами она открывает выбор тарифа, без них — +30 дней с вопросом.
- **Кто на каком тарифе** — сколько сейчас активных на каждом.

Кнопка **+ Выдать доступ** в углу главной заводит покупателя, не уходя в
«Клиенты». Денег панель не считает: платёжного шлюза у проекта нет, а
цена — пометка в тарифе для себя.

**Свежесть данных.** На главной, в клиентах, ключах, нодах и статистике
панель сама забирает данные заново раз в 30 секунд, пока вкладка открыта и
на виду; в шапке написано, сколько секунд назад пришёл последний ответ.
Скрытая вкладка и открытое окно действия опрос останавливают. На страницах
оповещений, журнала, обновлений и вида панель сама не обновляется: в полях
настроек перерисовка стёрла бы набранное.

### Поиск и фильтры клиентов

Над списком клиентов — поиск по имени и номеру у бота и готовые фильтры с
числом клиентов в каждом: **Истекают за 7 дней**, **Кончается трафик**
(меньше десятой части), **Не заходили неделю**, **Отключены** и по одному на
каждый тариф. Фильтр складывается с поиском и запоминается в браузере.

**Со списком.** Справа от фильтров — кнопка «Со списком · N»: одно действие
сразу со всеми, кого сейчас показывает список. Продлить по тарифу (или +30
дней, если тарифов нет), включить, отключить, обнулить расход, удалить.
Отбери фильтром «Истекают за 7 дней» — и продли всех разом. Там же —
выгрузка всех клиентов в CSV для учёта: имя, срок, тариф, расход; ключей и
ссылок в ней нет, а метки, похожие на формулы Excel, выгружаются текстом.

**Галочками.** У каждой строки — галочка, в шапке — «все на странице».
Отметка живёт между листами таблицы; над таблицей появляется полоса
«Выбрано: N» с теми же действиями и кнопкой «Удалить». Удаление спрашивает
отдельным окном, а API требует повторить число (`"confirm": N` в
`POST /api/v1/users/bulk` с `"action": "delete"`): опечатка в списке номеров
никого не сотрёт. Удалённых не вернуть — если сомневаешься, отключи.

### Тарифы

Кнопка **Тарифы** на странице «Клиенты». Тариф — шаблон: название, срок в
днях, трафик, устройства, скорость и пометка для себя (обычно цена; панель её
не считает). Заведи «Месяц · 50 ГБ · 2 устройства» и «Год» — дальше:

- **Новый клиент** — выбор тарифа одной кнопкой. «Свои значения вместо
  тарифа» открывают прежние поля для особого случая.
- **Продлить** в карточке — по тарифу: срок прибавляется к текущему
  окончанию (или к сегодня, если доступ истёк), лимиты становятся тарифными, а
  расход начинается заново — это новый оплаченный период. Без тарифов кнопка
  по-прежнему добавляет 30 дней.
- **Обнулить расход** в карточке — подарить трафик или исправить ошибку, не
  трогая срок. Ноды узнают об этом со следующей синхронизацией и пускают на
  весь лимит заново.
- **Изменить** в карточке — имя, заметка, срок до даты или бессрочно,
  трафик, устройства и скорость. Заметка («оплатил налом») видна только в
  панели: ни бот, ни ноды её не получают.
- **Метки** — в «Изменить», через запятую: «опт, семья». По ним фильтруют
  список, ищут и выгружают; бот может поставить их сразу при продаже
  (`tags` в `POST /api/v1/users`).
- **Выгрузить CSV** на странице «Клиенты» — таблица всех клиентов для своей
  бухгалтерии: открывается в Excel по столбцам, имя-формула в ней
  обезврежено. Только для админа, бот выгрузку не получает.
- **Ещё…** в карточке — редкое и опасное, подальше от «Продлить»:
  - **Заморозить** — доступ выключается, а при разморозке срок сдвигается
    на время паузы: клиент, уехавший на месяц, не теряет и не получает
    лишних дней. «Включить» и продление по тарифу размораживают так же;
  - **Сбросить устройства** — когда клиент сменил телефон и упёрся в лимит:
    адреса, с которых он приходил раньше, ноды перестают считать со
    следующей синхронизацией, а не через час;
  - **Сменить адрес подписки** и **Удалить**.
- **Сброс трафика** — каждые сутки, неделю, месяц или год: для «Года,
  50 ГБ в месяц» или «5 ГБ в сутки». Расход обнуляется сам по расписанию,
  считая от покупки или последнего продления: месячный — в тот же день
  месяца (купивший 31-го получает сброс в последний день коротких
  месяцев), годовой — в тот же день года (купившему 29 февраля — 28-го),
  суточный и недельный — в тот же час. Календарь московский. Срок и лимиты не меняются. Когда
  следующий сброс — видно в карточке клиента рядом с расходом, сами сбросы —
  в журнале с меткой «по расписанию». Истёкшим расход не обнуляется: продлят —
  продление начнёт расход заново. Продление по тарифу без сброса расписание
  снимает.

**Отчёт за месяц** — «Статистика» → «Отчёт за месяц»: новые клиенты,
продления, промокоды, у кого кончился срок и не продлён, и расход по нодам —
числами, за любой из последних двенадцати месяцев.

**Тексты для бота** — «Оповещения» → «Тексты для бота»: что написать
покупателю, когда он заведён, продлён, когда кончился срок или трафик.
Панель подставит имя, дату и остаток и пришлёт текст в вебхуке полем `text`.

**Промокоды** — «Тарифы» → «Промокоды»: код («LETO7») даёт дни и гигабайты,
один раз на клиента; можно ограничить число людей и последний день. Бессрочному
дни не добавляются, безлимитному — гигабайты. Применяет бот
(`POST /api/v1/users/{id}/promo` с `{"code": "LETO7"}`) или продавец в карточке:
«Ещё…» → «Применить промокод».

**Пробный тариф** — галочка «Пробный» у тарифа: выдаётся один раз на
человека и только с ключом продавца (`external_id`). Повтор — `409`, даже
если продавец удалил клиента и завёл заново: панель помнит хеш ключа, а не
сам номер. Пробным не продлевают.

**Рефералы** — «Тарифы» → «Рефералы»: сколько дней дать тому, кто привёл
платного покупателя; за пробного награды нет. Кто кого привёл, бот передаёт
полем `referrer` (ключ продавца пригласившего) при продаже. В карточке видно,
кого человек привёл и от кого пришёл.

Тариф — шаблон, а не подписка: правка или удаление тарифа уже купивших не
меняет — их срок и лимиты свои до следующего продления. Заводить и править
тарифы может только админ; бот их читает и продаёт по номеру (см.
[bot.md](bot.md#тарифы)).

**Как отправить доступ.** В окне выданных ссылок — **Скопировать для
Telegram**: ссылка и три строки, что с ней делать. У каждой ссылки есть
**QR-код** — его рисует сама панель, ссылка с доступом никуда наружу не
уходит.

### Флаги стран в чужих приложениях

Happ, Hiddify, v2RayTun и v2rayNG рисуют флаг, только если название ноды
начинается с эмодзи флага, — отдельного поля для страны в ссылке нет. Панель
ставит флаг сама: в ссылках `vless://` и `trojan://` и в профилях sing-box и
Clash название ноды начинается с флага её страны — «🇫🇮 Финляндия · Хельсинки».
Страна узнаётся по полю «Страна» ноды тем же словарём, что у приложения
Android; незнакомое название остаётся без флага — не тот флаг хуже никакого.
В ссылках `marvia://` флага нет: приложения Marvia рисуют его сами, а окно на
ПК убирает эмодзи-флаг из названий чужих подписок — Windows показывает его
двумя буквами.

### Профили sing-box и Clash

Ссылки `vless://` и `trojan://` берут v2rayNG, Hiddify, Happ и v2RayTun. А
sing-box (SFI на iPhone, SFM на Mac, SFA на Android), Stash, Clash Verge и
FlClash ждут готовый профиль. Панель отдаёт его по той же ссылке подписки
с явным форматом:

- `https://панель/sub/<токен>?format=singbox` — профиль sing-box 1.12 и
  новее: TUN, выбор ноды и автовыбор по задержке, запросы имён через
  туннель по HTTPS;
- `https://панель/sub/<токен>?format=clash` — профиль Clash Meta (mihomo):
  ноды, группа «Marvia» с автовыбором, всё кроме локальных сетей — через неё.

Обе ссылки есть в окне ссылок клиента. Формат выбирается только явно: по
User-Agent приложение не узнаём, потому что Hiddify, например,
представляется и как Clash, и как sing-box. VP1 эти приложения не знают,
поэтому в профиле — VLESS и Trojan; клиенту без них панель профиль не
отдаёт и говорит, чего не хватает.

### Поддержка, продление и объявление для покупателей

На той же странице **Оповещения** — второй блок: ссылка поддержки, ссылка
«Продлить» и объявление. Покупателю, у которого кончился срок или пропала
связь, должно быть куда нажать; без этого он ищет переписку с продавцом или
пишет «у вас всё лежит» туда, где его никто не ждёт.

- **Поддержка** — куда писать, если не работает: `https://t.me/…` или
  `tg://resolve?domain=…`.
- **Продлить** — страница оплаты или бот продавца. Платёжного шлюза у проекта
  нет (почему — в конце README): ссылка ведёт к продавцу, а продлевает его бот.
- **Объявление** — одна строка для всех, до 300 символов: работы, новости.

Пустое поле — выключено. Ссылки принимаются только `https://` и `tg://`:
ссылку приложение отдаёт системе, и `http:` подменил бы провайдер, а `file:`
или `intent:` открыли бы на телефоне не страницу. Русский домен вписывается в
виде `xn--…`. Из объявления уходят переводы строк, управляющие символы и
символы направления письма — те, которыми переворачивают текст, чтобы адрес
читался не тем, чем является.

Всё это уходит в подписку каждому покупателю: чужим приложениям — заголовками
`support-url`, `profile-web-page-url` и `announce` (в `base64:`, чтобы
кириллица дошла целой), нашему клиенту — полями `support_url`, `renew_url`,
`announce` в JSON. Happ, v2RayTun и Hiddify по ним рисуют кнопки и объявление
над профилем; Happ показывает первые 200 символов объявления. Заголовок
`profile-title` — метка доступа, то же имя, что уже стоит в названии каждой
ноды. Если метка пустая или после очистки в ней ничего не осталось, имя
профиля — `Marvia`: Hiddify иначе показал бы токен из конца ссылки подписки.
После обновления панели обновите профиль в приложении; если приложение
сохранило старое имя, переименуйте профиль или импортируйте ссылку заново.

Клиент панели не доверяет: ссылки и длину перепроверяет сам при каждом
приёме — из сети и из кэша, — и те же правила применяет к заголовкам чужих
подписок (3x-ui, Marzban, Remnawave). Ядро клиента сверх того считает
напоминание о сроке: за трое суток и за сутки до конца и когда трафика
осталось меньше десятой части, с ключом, чтобы одно и то же не повторять;
после продления напоминание снимается само.

В приложениях Marvia кнопки есть **на Windows** (см. «Канал продавца в
окне» в разделе про клиент для Windows) и **на Android** — на карточке
подписки в «Серверах», под сроком и остатком: объявление и кнопки
«Продлить» и «Поддержка», только те, чьи ссылки продавец оставил. Ссылку
Android отдаёт системе, проверив схему ещё раз; `tg://` без Telegram на
телефоне — короткое сообщение, а не тишина. Напоминание о сроке на телефоне —
уведомлением, когда приложение обновляет подписку; нажатие ведёт на
«Продлить», а нет такой ссылки — в приложение. Одно и то же напоминание
приходит один раз; без разрешения на уведомления оно не тратится и придёт,
когда разрешат. Покупатели Happ, v2RayTun и Hiddify видят ссылки и
объявление тоже.

Правку могут делать только админским токеном, читать — и ключом бота с
правом `read`; запись в журнале — «связь с покупателем». API — в
[bot.md](bot.md#поддержка-продление-объявление).

### Копии базы

`panel.db` — это весь бизнес продавца: покупатели, сроки, оплаченные месяцы.
Ноды расходник и теряются штатно, панель незаменима. Сервер умер или хостер
снёс его по жалобе — и продавец не может даже сказать людям, до какого числа у
них оплачено.

Копию снимает **сама панель**, раз в сутки, в `backup` рядом с базой; хранится
семь последних. Продавец, которому надо помнить про cron, однажды про него не
вспомнит.

| Ключ | Что делает |
|---|---|
| `-backup-dir` | куда складывать (по умолчанию — `backup` рядом с базой) |
| `-backup-keep` | сколько держать, по умолчанию 7 |
| `-backup-every` | как часто, по умолчанию раз в сутки; `0` — не снимать |
| `-backup-key` | публичный ключ: копии шифруются им и становятся нечитаемыми без приватного |

Копия снимается через `VACUUM INTO`, а не копированием файла: база живёт в
режиме WAL, и скопированный на ходу `panel.db` — это состояние на момент
последней контрольной точки, без покупателей за последние минуты. Панель при
этом продолжает работать, читатели не блокируются.

### Копии вне сервера по расписанию

Копия, которая лежит рядом с базой, умирает вместе с сервером. Поэтому
панель умеет раз в сутки отправлять зашифрованную копию наружу: в чат
оповещений Telegram (бот уже настроен для оповещений) и/или в
S3-совместимое хранилище. Настройка — «Оповещения» → «Резервные копии вне
сервера» (расширенный режим): время по UTC, сколько последних копий
хранить, пароль, куда отправлять. «Отправить копию сейчас» проверяет всё
сразу.

**Пароль на сервере не хранится.** Из него через scrypt выводится пара
ключей; панель запоминает только соль и **публичный** ключ — шифровать
может, открыть не может. Без пароля расписание не включается: незашифрованная
копия в Telegram — то же, что база в открытом чате. Потерянный пароль не
восстановить; после смены пароля старые копии открываются старым.

**Сколько хранится.** В Telegram последние N копий — это N сообщений:
самый старый документ заменяется новым. В S3 старые объекты удаляются
только после успешной загрузки новой копии и только под префиксом этой
панели. S3-клиент свой, на стандартной библиотеке, с подписью AWS SigV4
(проверена на опубликованных примерах AWS), — без SDK на весь бинарник.

**Сбой — оповещение.** Копия не снялась или не ушла — в чат оповещений
придёт сообщение; недоставленное оповещение повторяется.

**Проверить, что из копии можно восстановиться**, — на любом компьютере:

```bash
MARVIA_BACKUP_PASSWORD='пароль' marvia-panel -verify-backup panel-2026-10-05.db.sealed
```

Команда расшифровывает копию, открывает базу без миграций, проверяет схему
и целостность и печатает число клиентов и нод. С `-backup-output
восстановленная.db` она ещё и сохраняет расшифрованную базу — её можно
подложить панели вместо `panel.db`. Без переменной пароль читается из
stdin, чтобы не оставаться в истории команд.

**Восстановить из копии кнопкой** — «Оповещения» → «Восстановить из копии…»:
файл «Копии базы» (`.db`) или парольная копия с паролем. Панель проверяет
целостность и что это база Marvia, доводит схему до своей версии на самой
копии, перезапускается и при запуске встаёт на неё. Нынешняя база не
удаляется — она ложится рядом как `panel.db.before-restore-<дата>`. Копию
с ключом (`marvia-keygen -backup`) сначала расшифруй сам: приватного ключа
у панели нет. Перезапуск идёт через службу (`Restart=on-failure`):
запущенная руками панель после восстановления просто остановится — запусти
её снова.

### Шифрование копий

Копия — это вся панель целиком: люди, их телеграм-идентификаторы, токены
подписок, секреты vless и trojan. И она специально уезжает с сервера — иначе
теряется вместе с ним. Дальше живёт в облаке, на ноутбуке, иногда в переписке.

Поэтому её можно зашифровать так, чтобы **ключа для чтения на сервере не
было вовсе**:

```bash
./bin/marvia-keygen -backup
```

Публичный ключ отдаётся панели, приватный — себе:

```bash
marvia-panel -backup-key <публичный ключ> …
```

С этого момента копии складываются с окончанием `.sealed`. Панель умеет их
зашифровать и **не умеет открыть** — приватного ключа у неё нет. Открыть
можно там, куда копию увезли:

```bash
marvia-keygen -open-backup panel-2026-09-13-1529.db.sealed -key <приватный ключ>
```

Почему не пароль. Чтобы шифровать по расписанию, панель должна знать пароль
во время работы — то есть он лежал бы в unit-файле рядом с базой, и изъятие
сервера выдавало бы и копии, и ключ к ним. Публичным ключом шифруют не зная
приватного, и это ровно то, что здесь нужно.

Примитив взят готовый: `crypto_box_seal` из `nacl/box` — X25519, XSalsa20 и
Poly1305. На каждую копию берётся одноразовая пара ключей, так что по двум
файлам нельзя сказать даже того, что они сняты одной панелью.

**Чего это не даёт.** От изъятия работающего сервера не спасает: там есть сама
база, открытая. Шифрование копий закрывает ровно то, что и должно, — копию,
которая уехала и живёт своей жизнью.

**Потерянный приватный ключ означает потерянные копии.** Открыть их нечем, и
это не фигура речи. Держи его там же, где держишь пароли, и не на сервере.

Приватный ключ можно передать и переменной `MARVIA_BACKUP_KEY` вместо `-key`.

Скачивание копии через панель (`GET /api/v1/backup`) отдаёт её **открытой**:
она едет по TLS в браузер того, кто уже вошёл админским токеном, и шифровать
её нечем — приватный ключ у него, а не у панели.

**Копия на том же сервере не спасает от потери сервера.** Забрать её к себе:

```bash
curl https://panel.example.com/api/v1/backup -H "Authorization: Bearer $MARVIA_ADMIN_TOKEN" -o panel.db
```

Ручка отдаёт свежий снимок, а не файл с диска. Только админским токеном:
в копии лежит всё — токены подписок, секреты vless и trojan, хеши ключей.
Ключ, которым можно её скачать, — это ключ, который может всё. Храни скачанное
соответственно.

Восстановление — это `cp`: положить файл на место `panel.db` и запустить
панель. Токены подписок и наборы доступа в копии те же, поэтому приложения
покупателей ничего не заметят.

### Что установщик проверяет до того, как что-то менять

Домен обязан вести на этот сервер — сверяется запись A с внешним адресом
машины. Проверка стоит первой: у Let's Encrypt ограничено число неудачных
попыток, и упереться в этот предел из-за неверной записи DNS — обидный способ
потерять час.

Порт 80 занят — отказ с объяснением, зачем он нужен. Порт панели занят —
отказ с предложением взять другой.

В конце установщик ждёт, пока панель действительно ответит по https, и при
неудаче печатает журнал.

### Секретов нет в командной строке

Админский токен уезжает в `EnvironmentFile` с правами 600. В строке запуска
его видел бы любой пользователь системы через `ps`. Панель, как и нода,
работает **не от root**: права нужны только чтобы занять порты ниже 1024.

## Установка ноды одной командой

Продавец просит у панели приглашение и получает готовую строку:

```bash
curl -X POST https://panel.example.com/api/v1/nodes/invite \
  -H "Authorization: Bearer $MARVIA_ADMIN_TOKEN"
```

```json
{
  "command": "curl -fsSL https://panel.example.com/install/<приглашение> | sh",
  "invite": { "expires_at": "…" }
}
```

Строку он вставляет на чистом сервере. Всё: ключи выпущены, нода записана в
панель, служба поднята и проверена. Ни одного флага, ни одного файла для
редактирования.

В панели то же самое — «Ноды» → «+ Нода». Окно не просто показывает строку,
а ведёт по шагам: «нода записалась в панель» → «нода на связи». Если за
четыре минуты нода не появилась, окно само показывает, что проверить на её
сервере и какой командой: видит ли сервер панель, не занят ли порт 443,
что пишет служба ноды, не закрыт ли порт файрволом.

Поменять что-то можно переменными, не трогая скрипт:

```bash
curl -fsSL https://panel.example.com/install/<приглашение> | PORT=8443 DEST=www.icloud.com:443 NAME=amsterdam-1 COUNTRY=Нидерланды sh
```

### Приглашение вместо админского токена

Установщику нужен доступ к панели, чтобы записать в неё новую ноду. Соблазн
был передать ему админский токен — и это была бы дыра во всё хозяйство: токен
осел бы на каждой ноде, а ноды стоят на дешёвых машинах в чужих странах и
живут под постоянным вниманием. Взлом одной такой машины отдал бы список
покупателей, их ключи и право выпускать новые доступы.

Поэтому — одноразовое приглашение. Оно даёт ровно одно право: **один раз
назваться нодой**. Живёт час, гасится в той же транзакции, в которой заводится
нода, и второй раз не срабатывает. Дальше нода работает своим токеном, которым
может только забирать свой список пользователей и сдавать расход.

`TestInviteOnlyWorksOnce` и `TestInviteGivesNoOtherRights` держат оба свойства.

### Установщик раздаёт сама панель

Скрипт и бинарники лежат по адресу `/install/<приглашение>`, а не на публичном
сайте. Причин две. Продавцу не нужно ничего нигде размещать — панель у него
уже есть. И посторонний, ткнувшийся в панель, ничего не найдёт: без живого
приглашения там обычный 404. Найденный установщик был бы однозначной вывеской
«здесь панель обхода блокировок».

Бинарники панель берёт из каталога `-dist`. Положить их туда — единственное
ручное действие при обновлении.

Разрядность нода называет сама (`?arch=arm64`): дешёвые машины под ноды
нередко ARM, а панель стоит на amd64. Панель отдаёт `marvia-node-arm64` из
`dist`, если он там есть, — установщик панели кладёт оба архива релиза, а
`upgrade.sh` обновляет оба. Файла под нужную разрядность нет — панель
отдаёт общий и заголовком `X-Marvia-Arch` говорит, для чего он собран;
установщик сверяет его со своей машиной и запускает скачанное с `-version`
до выпуска ключей, так что чужой бинарник останавливает установку, пока
приглашение ещё живо, а не после того, как оно сгорело.

В живом терминале установщик показывает знак Marvia, бегунок на долгих
шагах и полосу загрузки; в трубе или журнале — те же строки без украшений.
`NO_COLOR` уважается.

### Что установщик проверяет до того, как что-то менять

Порт занят — говорит об этом сразу, не скачав ни байта. Обнаружить занятость
после установки значит оставить человека с наполовину поставленной нодой.

Сайт прикрытия недоступен или не умеет TLS 1.3 — тоже отказ: с мёртвым
прикрытием нода не спрячется, а выяснилось бы это уже у покупателей.

Порт не 443 — предупреждение. Настоящие сайты на нестандартных портах не
живут, и это заметно со стороны; вдобавок корпоративные и гостиничные сети
такие порты режут.

В конце установщик ждёт, пока служба действительно поднимется, и при неудаче
печатает журнал. «Установка завершена» при упавшей службе — худшее, что он мог
бы сказать: человек уходит довольный, а работать начинает завтра.

### Адрес ноды определяет панель, а не нода

Нода не знает своего внешнего адреса: за NAT она видит внутренний, и в
конфигах покупателей оказалось бы `10.0.0.5`. Панель видит настоящий — тот, с
которого пришла регистрация, — и записывает его сама.

Если панель стоит за обратным прокси, адрес берётся из `X-Forwarded-For`, но
**только когда запрос пришёл из петли или частной сети**. Постороннему из
интернета заголовок не верим: иначе одного приглашения хватило бы, чтобы
записать ноду с чужим адресом — например с адресом сайта, который потом попал
бы в конфиги всех покупателей.

### Секретов нет в командной строке

Токен панели и приватный ключ REALITY уезжают в `EnvironmentFile` с правами
600, а ключ ноды лежит файлом и передаётся как `-key-file`. В строке запуска
их видел бы любой пользователь системы через `ps`.

Сама нода работает **не от root**: единственное, ради чего ей нужны были
права, — занять порт ниже 1024, и это выдаётся отдельной возможностью
`CAP_NET_BIND_SERVICE`.

### BBR для соединений ноды

Нода просит у ядра для своих соединений BBR вместо стандартного CUBIC.
Маршрут от ноды до покупателя почти всегда дальний и с потерями, и CUBIC
на каждую потерю вдвое сбавляет скорость; BBR держит её по измеренной
полосе. Алгоритм ставится на слушающий сокет ноды, системный по умолчанию
не меняется — остальные службы сервера его не замечают.

Установщик загружает модуль `tcp_bbr` и разрешает выбирать BBR без root
(`/etc/sysctl.d/90-marvia-bbr.conf`); `BBR=0` перед `sh` это отключает. Где
BBR нет, нода пишет об этом в журнал один раз и работает на стандартном.
На ноде, поставленной раньше, то же самое — одна команда на сервере ноды
от root:

```bash
modprobe tcp_bbr && echo tcp_bbr >/etc/modules-load.d/marvia-bbr.conf && { grep -qw bbr /proc/sys/net/ipv4/tcp_allowed_congestion_control || printf 'net.ipv4.tcp_allowed_congestion_control = %s bbr\n' "$(cat /proc/sys/net/ipv4/tcp_allowed_congestion_control)" >/etc/sysctl.d/90-marvia-bbr.conf; } && sysctl -q --system && systemctl restart marvia-node
```

Замера на живом маршруте с BBR пока нет; прирост здесь не обещается.

## Вход в России: каскад

Зарубежные адреса режут подсетями хостеров целиком, а при белых списках
мобильный интернет пускает только к своим, российским адресам. Маскировка
здесь не помогает: блокируют адрес, а не то, что по нему ходит. Помогает
вход — сервер в российском облаке (Яндекс Облако, Selectel, VK Cloud), к
которому покупателя пропустят. Вход перекладывает соединение на зарубежную
ноду, и от облака до неё связь уже обычная, межсерверная.

Ставится из панели: «Ноды» → нода → **«Вход в России»**. Панель выдаёт ту
же строку `curl … | sh`, только установщик по этому приглашению ставит
перекладчик: без ключей и без сайта прикрытия, службой `marvia-node -relay`.
Порт и имя задаются так же, переменными перед `sh`:

```bash
curl -fsSL https://panel.example.com/install/<приглашение> | PORT=443 NAME=Москва sh
```

**Что знает вход.** Только адрес своего выхода: его говорит панель при каждой
сверке. Ключей у входа нет, список покупателей ему не отдаётся, шифрование —
TLS, REALITY и VP1 — идёт насквозь от покупателя до выхода. Изъятый вход
выдаёт адрес выхода, который и так виден по его трафику. Журнала «кто
откуда» вход, как и нода, не ведёт.

**Что видит покупатель.** В подписке вход — отдельная строка: страна,
ключи и маскировка выхода, адрес входа, имя вида «Хельсинки · вход Москва».
Клиенты замеряют его наравне с прочими и сами берут его, когда прямой путь к
выходу закрыт. QUIC через вход не идёт: вход перекладывает только TCP.

**Адрес покупателя доходит до выхода.** Нода считает устройства покупателя
по адресам; через вход все покупатели пришли бы с одного адреса, и лимит
устройств перестал бы значить что-либо. Поэтому вход первым делом шлёт
выходу заголовок PROXY protocol v2 с адресом покупателя. Выход верит ему
только от адресов своих входов — их ему называет панель: адрес из записи
входа и адрес, с которого вход с ней сверяется.

**Что проверяет панель.** Выходом бывает только обычная нода: не сам вход
и не нода за CDN — у той адрес и так скрыт, а сырые байты CDN не поймёт.
Нода старше 0.13.0-alpha.24 заголовка входа не понимает и приняла бы его за
мусор, поэтому вход к ней панель не выдаёт, пока её не обновят. Выход у
входа меняется в его окне; новый доезжает до входа за одну сверку, без
перезапуска. Выключенный выход — пустой адрес у входа: тот перестаёт
перекладывать, а не ведёт покупателей туда, откуда продавец их убрал.

**Цена.** Лишний переход: задержка растёт на путь от входа до выхода,
обычно на 20–50 мс из Москвы до Европы. И сам вход — ещё одна машина,
за которую платит продавец. Если панель недоступна, вход по снимку помнит
выход до 24 часов, как нода помнит доступы.

**Если вход «молчит».** Вход — такая же запись ноды: «на связи», версия и
обновление кнопкой у него свои. Если панель и вход стоят в одной внутренней
сети облака, адрес, с которого вход сверяется с панелью, может не совпасть с
тем, с которого он ходит к выходу, — тогда выход не узнает своего входа и
покупатели через него не подключатся. Ставь вход и панель на разные машины
или проверь адрес входа в его окне.

## Хостер, обслуживание и группы нод

В листе ноды — раздел «Хостер, обслуживание, группы».

**Лимит у хостера.** Сколько гигабайт в месяц даёт тариф VPS и с какого
числа хостер считает заново (1–28). В карточке ноды виден расход за текущий
период, на 90% приходит оповещение в Telegram — время перевести людей на
другие ноды, пока хостер не урезал скорость или не выставил счёт.

**Обслуживание.** Окно «с — до», разовое и не длиннее месяца. Пока оно идёт,
нода пропадает из подписок, панель отвечает ей «выключена», и она перестаёт
пускать; клиенты Marvia сами переезжают на живую ноду. После окна нода
возвращается сама. «Закончить обслуживание» снимает окно раньше.

**Группы.** Для кого нода, через запятую: «premium». Нода без групп — для
всех; с группами — видна в подписке и пускает только покупателей своей группы:
«премиум» держится не на том, что ссылку не раздали. Группу покупатель
получает из тарифа (поле «Группа нод») или из «Изменить» в карточке.

## Защита от флуда

Нода, вход каскада и панель держат пределы на поток соединений и запросов.
Это защита от дешёвого и частого: несколько машин открывают тысячи
соединений в секунду или перебирают токены подписок, и сервер тратит память
и базу на то, что никогда не станет покупателем. Значения по умолчанию
выбраны с запасом под обычную нагрузку (`internal/connguard`,
`internal/panel/flood.go`); пределы нод продавец меняет в панели.

**Настройка в панели.** «Ноды» → **Защита**. Наверху — сколько каждая нода
отбила за сутки и почему: слишком часто с одного адреса, сверх предела
открытых, из закрытых адресов. Ниже — три предела (пустое поле — значение
по умолчанию) и список закрытых адресов и сетей, по одному в строке:
`203.0.113.7` или `198.51.100.0/24`. Ноды и входы каскада применяют это
со следующей синхронизацией, без перезапуска; уже открытые соединения не
рвутся. Панель не даёт заперть ноду опечаткой: частота — не меньше одного
соединения в секунду, сеть — не шире /8 для IPv4 и /32 для IPv6, адресов —
не больше тысячи. Закрытый адрес не пускается и как вход каскада: закрыть
его — решение продавца. Менять защиту может только админ, не бот.

**Чего эти пределы не делают.** Объёмный DDoS — гигабиты мусора в канал —
программой на самом сервере не лечится: канал забит раньше, чем пакет дошёл
до кода. От него помогают хостер с защитой от DDoS, режим CDN (раздел
«Работа за CDN» выше), вход каскада в другой сети и запасные ноды в подписке:
клиент сам переезжает на живую. Если ноду завалили, не трать время на её
настройки — переноси покупателей.

**Нода и вход каскада.** Пределы стоят первыми, над сырым TCP, до заголовка
PROXY, TLS и REALITY:

- 20 новых соединений в секунду с одного адреса, запас на пик — 200. Именно
  частота новых, а не число открытых: за одним адресом мобильного оператора
  (CGNAT) сидят сотни покупателей, и каждый держит свои соединения часами.
  IPv6 считается по сети /64 — её получает один абонент;
- 20 000 открытых соединений на ноде всего (у входа — 8192).

Входы каскада от предела частоты на выходе освобождены: за адресом входа
приходят все его покупатели. Какие адреса — входы, говорит панель. Нода за
CDN (`-ws-path`) предела частоты не держит вовсе: все её покупатели приходят
с адресов узлов CDN, и флуд там принимает на себя CDN; общий предел
открытых остаётся. Сверх
предела соединение сбрасывается сразу, без ответа. В журнал раз в минуту
уходит одна строка — сколько отклонено и почему, без адресов:

```
за минуту отклонено соединений: 4810 — слишком часто с одного адреса, 0 — сверх предела в 20000 открытых
```

QUIC (UDP) этот слой не трогает.

**Панель.**

- 30 запросов в секунду с адреса, запас 120. Сверх — 429 с `Retry-After`.
  Страница панели спрашивает раз в полторы секунды, ноды сверяются раз в 15
  секунд — это на порядок ниже;
- сто неудач за десять минут с одного адреса — и десять минут этот адрес
  получает 429 на всё. Неудача — это 401 (неизвестный токен) или 404 вне
  `/api/v1/` (неизвестная подписка или приглашение). 403 неудачей не
  считается: его получает тот, чей токен настоящий, — бот без нужного права
  или выключенная нода. Нода с отозванным токеном узнаёт об отзыве с первого
  же 401, задолго до блокировки;
- 512 запросов в работе одновременно. Сверх — сразу 503, без похода в базу.

В журнал панели, как и у ноды, не чаще раза в минуту идёт только число
отклонённых.

Запросы с этой же машины и из частной сети не ограничиваются по адресу: так
приходят бот продавца, стоящий рядом, и обратный прокси. Адрес за прокси
панель берёт из `X-Forwarded-For`, только если прокси стоит на этой машине
или в частной сети, и берёт первый адрес из заголовка, — прокси должен
заменять заголовок, а не дописывать к нему.

**Панель за Cloudflare.** Заголовкам от публичных адресов панель не верит,
иначе любой подставлял бы себе новый адрес на каждый запрос. Поэтому за
Cloudflare адресом считается узел Cloudflare, через который пришёл запрос, а
не покупатель. Пределы рассчитаны так, что обычная нагрузка через один узел
в них укладывается: 30 запросов в секунду — это сто тысяч в час. Но флудер,
пришедший через тот же узел, делит предел с покупателями, и блокировка за
перебор достаётся всем, кто ходит через этот узел. Приложение с сохранённым
списком нод на эти десять минут остаётся на нём и подключается, но новую
подписку не получит. Защищать панель за Cloudflare от флуда должен сам
Cloudflare — правилами ограничения частоты в его настройках.

## Переезд с Marzban и 3x-ui

Покупатели переезжают со своим: UUID VLESS, паролем Trojan, сроком,
остатком квоты и адресом подписки. Продавцу не нужно рассылать новые
ссылки — это и было главной ценой переезда.

Читает прежнюю базу сама панель. Поддержаны Marzban на SQLite (так он
ставится по умолчанию) и 3x-ui на SQLite, ветки 2.x и 3.x. Базы в MySQL и
PostgreSQL пока не читаются.

**1. Скопировать базу на сервер панели.** Копию лучше снимать, остановив
прежнюю панель на минуту: файл SQLite, в который пишут прямо сейчас,
копируется не целиком. Для Marzban нужен ещё `xray_config.json` — в нём
ключи REALITY. Команды — на сервере панели Marvia:

```bash
mkdir -p /root/old && scp root@СТАРЫЙ-СЕРВЕР:/var/lib/marzban/db.sqlite3 root@СТАРЫЙ-СЕРВЕР:/var/lib/marzban/xray_config.json /root/old/
```

```bash
mkdir -p /root/old && scp root@СТАРЫЙ-СЕРВЕР:/etc/x-ui/x-ui.db /root/old/
```

**2. Прочитать отчёт.** Без `-import-apply` панель только показывает, что
переедет, и ничего не пишет:

```bash
/opt/marvia/marvia-panel -db /opt/marvia/panel.db -import marzban -import-db /root/old/db.sqlite3
```

Для 3x-ui — `-import 3x-ui -import-db /root/old/x-ui.db`. В отчёте:
сколько покупателей переедет, какие входы прежней панели нода Marvia примет
как есть, у кого ссылки сменятся и почему, и строка для установщика ноды.

**3. Записать.** Панель на это время останавливается, чтобы две записи в
одну базу не столкнулись. Файлам базы перенос возвращает прежнего хозяина
сам: запущенный от root, он не оставит службе файлов, которые та не
откроет.

```bash
systemctl stop marvia-panel && /opt/marvia/marvia-panel -db /opt/marvia/panel.db -import marzban -import-db /root/old/db.sqlite3 -import-apply; systemctl start marvia-panel
```

Повторный запуск безопасен: уже перенесённые узнаются по имени на прежней
панели и не заводятся второй раз. Секрет, который у прежней панели был у
двух покупателей сразу, достаётся первому — второй попадёт в список «не
перенеслось».

**4. Поставить ноду на прежний сервер.** Если входы прежней панели —
VLESS или Trojan под REALITY по TCP, нода Marvia с теми же ключами примет
прежние ссылки без изменений. Сначала прежнюю панель останавливают — она
держит порт:

```bash
marzban down
```

```bash
x-ui stop
```

Затем в панели Marvia **Ноды → + Нода**, и в выданную строку перед `sh`
вставляется то, что напечатал отчёт:

```bash
curl -fsSL https://panel.example.com/install/ПРИГЛАШЕНИЕ | PORT=443 DEST=www.google.com:443 SNI=www.google.com SHORT_IDS=a1b2 REALITY_KEY=… REALITY_PUB=… sh
```

TLS со своим сертификатом и WebSocket нода тоже умеет, но установщик ставит
только REALITY: такую ноду настраивают флагами `-tls-cert` или `-ws-path`
(см. «Работа за CDN»).

**5. Перевести адрес подписки.** Прежние адреса работают, когда домен и
порт, с которых их отдавала прежняя панель, ведут на панель Marvia. Проще
всего ставить панель Marvia сразу на этот домен: у Marzban это домен его
панели, у 3x-ui — домен подписки (`subDomain`) и её порт, обычно 2096:

```bash
sh install-panel.sh --domain sub.example.com --port 2096 --email you@example.com
```

Путь подписки, если он был не `/sub/` (у 3x-ui его часто делают
случайным), панель узнаёт из базы сама. У Marzban путь живёт в `.env`
(`XRAY_SUBSCRIPTION_PATH`) — его передают в `-import-sub-path`.

Приложение покупателя само обновит подписку по прежнему адресу и получит
ссылки на ноды Marvia. Поэтому адрес подписки важнее отдельных ссылок:
он чинит и те, что нода как есть не примет.

### Что не переезжает

- **VMess и Shadowsocks.** Нода Marvia их не понимает. Покупателю, у
  которого больше ничего не было, выдаётся новый VLESS — он придёт с
  подпиской.
- **Ссылки с Vision** (`flow=xtls-rprx-vision`) и транспорты gRPC, XHTTP.
  Прежние ссылки перестанут работать, новые придут с подпиской.
- **Форматы Clash и sing-box.** Marzban подбирал формат под приложение по
  его User-Agent, Marvia — только по явному адресу: `?format=clash` и
  `?format=singbox` (см. «Профили sing-box и Clash»). Прежняя ссылка в Clash
  Verge или Stash получит список ссылок и не загрузится — такому покупателю
  нужно отправить ссылку профиля Clash из окна ссылок.
- **Сброс квоты по расписанию и «срок с первого подключения».** Таких
  режимов у Marvia нет. Расход до переезда входит в квоту, а срок, который
  ещё не начинался, отсчитывается с переезда — отчёт называет таких
  покупателей поимённо.
- **Общий лимит входа 3x-ui.** Переносятся лимиты каждого покупателя.

Смена ссылки подписки в панели гасит и прежние адреса: ссылку меняют,
когда она утекла, а утечь могла как раз старая.

## Обновление кнопкой: панель и ноды

Начиная с 0.12.0 каждый сервер один раз переводят на проверку подписанного
релиза. Нужен GitHub CLI с `gh attestation verify`; команды проверки подписи
до запуска скрипта и порядок перехода — в [руководстве 0.12](release-0.12.md).

Дальше — страница «Обновления» в панели: версия панели и последний релиз,
версия и разрядность каждой ноды, кнопки «Обновить панель», «Обновить N нод»
и «Обновить всё» — панель и отставшие ноды одним нажатием. «Проверить сейчас»
спрашивает GitHub сразу, а не ждёт своего часа; не чаще раза в двадцать
секунд, сколько ни жми.

Пока идёт обновление, страница показывает его шагами: просьба, выпуск,
подпись, установка, перезапуск, готово. Шаг служба пишет в своё состояние
(`/var/lib/marvia-upgrade/status`), панель опрашивает его раз в полторы
секунды. У ноды в пути — бегущая полоска, пока её версия не дойдёт до
целевой. Когда панель поднялась на новой версии, страница перезагружается
сама. Служба запускается не чаще раза в пять минут; просьба, пришедшая
раньше, получает ответ «повторю через N с», и открытая страница повторяет её
сама, когда срок выйдет.

**Ночное автообновление.** Переключатель на той же странице: в выбранный час
по Москве (по умолчанию 04:00) панель проверяет свой канал и, если вышло
новее, просит отставшие ноды и службу на своей машине — то же, что «Обновить
всё». Один выпуск за ночь просится один раз. Ставит та же служба с проверкой
подписи; не поднялась новая версия — возвращается прежняя. В журнале такие
действия записаны от имени «автообновление».

Панель и нода работают от `marvia` и могут менять файлы своих каталогов,
поэтому их содержимое нельзя исполнять от root. Обновляет отдельная служба
`marvia-upgrade.path` / `.service`: она удаляет файл-просьбу, не читая его,
выбирает официальный тег GitHub и скачивает скрипт, SHA256SUMS и подпись.
GitHub CLI проверяет происхождение манифеста: репозиторий, workflow,
точный тег и GitHub-hosted runner. Затем проверяются суммы скрипта и архива.
Все файлы одной попытки берутся из одного тега. При ошибке проверки установка
не начинается. Подробнее о границах доверия — в руководстве перехода.

Имя репозитория в подписи сверяется без учёта регистра. Репозиторий
переименован из `jytt8u/marvia` в `jytt8u/Marvia`, и выпуски до и после
подписаны разным написанием, а GitHub регистр не различает. Workflow и метка
сверяются точно.

Корни доверия Sigstore gh скачивает с `tuf-repo-cdn.sigstore.dev`, а тот
открывается не со всех хостингов. Тогда gh отвечает «public good verifier is
not available», и служба проверяет подпись ещё раз — корнем
`/usr/local/lib/marvia/sigstore-root.jsonl`. Этот корень встроен в бинарник и
ставится вместе со службой, то есть приехал в уже проверенном выпуске. Под
него подделать подпись не легче, чем под свежий. Устаревший корень даст
отказ, а не пропуск. Свежесть корня проверяет CI.

`upgrade.sh` не запускает установленный бинарник даже для определения версии.
Копия бинарника для отката хранится во временном каталоге root. Если новая
служба не запускается или за минуту не открывает TCP-слушатель своим MainPID,
возвращаются прежний бинарник и копия базы. Проверку реального VPN-подключения
после выкладки выполняют отдельно.

Копия базы перед обновлением лежит в `/var/backups/marvia` (каталог root,
права 700), а не рядом с базой. В каталог панели root не пишет: файлы службы
он читает и возвращает правами её владельца через `runuser` из util-linux.
Иначе взломанная панель могла бы подложить ссылку на имя копии, и root
записал бы базу туда, куда она указывает.

Состояние и журнал лежат в `/var/lib/marvia-upgrade`, принадлежащем root.
Панель их читает. Просить обновление можно не чаще раза в пять минут;
содержимое просьбы не задаёт адрес скачивания или исполняемую команду.

**Ноды.** Нода сообщает панели свою версию и разрядность в каждом отчёте.
Кнопка ставит пометку «обнови до такой-то» включённым нодам, чья версия
старше релиза, — именно старше: нода из свежей сборки бывает новее релиза, и
«обновись до релиза» откатило бы её назад. Нода узнаёт о пометке при
очередной сверке, в течение четверти минуты, и кладёт просьбу своей службе;
если та не справилась, через полчаса нода попросит снова. Дошедшая нода
снимает пометку сама. Выключенные ноды не трогаются: продавец убрал их из
работы, и менять им бинарник у него за спиной незачем.

Нода, поставленная до 0.12, версию не сообщает и просьбу не услышит — такую
один раз обновляют той же командой на её сервере; панель её так и помечает.

**Совместимость.** Ноды обновляются не разом с панелью, поэтому в `/node/*`
поля только добавляются, а панель незнакомые поля от нод пропускает, а не
отвергает. Панель 0.11 разбирает отчёт строго и на поле `version` отвечает
400; нода тогда повторяет отчёт в прежнем виде — расход дороже версии — и
полчаса версию не шлёт.

**Номер последнего релиза** панель узнаёт у `github.com/…/releases/latest`:
GitHub отвечает переадресацией на `…/tag/vX.Y.Z`, и номер берётся из адреса.
Только когда открыта страница «Обновления» или пришёл час автообновления:
в тестовом канале не чаще раза в двадцать минут, в стабильном — раз в час.
Не видит GitHub — страница так и говорит, а кнопка нод не нажимается: просить
обновиться неизвестно до чего нельзя.

**Тестовый канал.** `releases/latest` у GitHub — только стабильный выпуск,
поэтому alpha и beta кнопка по умолчанию не предлагает. Получать их можно,
переключив канал машины от root:

```bash
curl -fsSL https://raw.githubusercontent.com/jytt8u/marvia/main/scripts/upgrade.sh | MARVIA_CHANNEL=test sh
```

Команда записывает выбор в `/var/lib/marvia-upgrade/channel` и сразу ставит
самый новый опубликованный выпуск. Дальше этим же каналом пользуется служба
по кнопке. Самый новый — по номеру, а не по дате: правка старой ветки,
вышедшая позже, сервер не откатит. Черновики GitHub в ленту меток попадают,
но файлов снаружи не отдают и поэтому пропускаются. Панель канал только
читает и показывает: переключать его по кнопке значило бы дать взломанной
панели ставить серверу сборки, проверенные меньше.

Канал у каждой машины свой. Ноду тоже переключают командой на её сервере:
нода на стабильном канале тестовый выпуск не поставит, даже если панель
попросит. `MARVIA_CHANNEL=stable` возвращает стабильный канал без отката:
после удачной установки `upgrade.sh` записывает версию в
`/var/lib/marvia-upgrade/installed`, и ни служба, ни сценарий не ставят
выпуск старше записанного. Старая панель поверх базы, которую уже перестроила
новая, — потеря данных, а не обновление.

Тестовые выпуски сравниваются целиком: alpha.5 раньше alpha.6, alpha раньше
beta и rc, все они раньше выпуска с тем же номером без хвоста.

**Чего пока нет.**

- Обновления нод, которые не видят GitHub (российские хостеры, Иран): служба
  берёт релиз только оттуда. Чтобы ноду мог обновлять и сам сервер панели,
  нужна подпись релиза, которую нода проверит без доверия к панели, — иначе
  взломанная панель раздала бы нодам что угодно. Это следующий шаг.
- Поэтапной раскатки: кнопка просит все отставшие ноды разом. Каждая
  перезапускается на секунды, покупатели переподключаются сами.
- Проверка «поднялась» — это «служба `active` за 15 секунд», то есть процесс
  запущен, а не «принимает соединения».

## Имя, страна и выключение ноды

В окне новой ноды имя и страна вписываются сразу и встают в команду
переменными (`NAME='fi-2' COUNTRY='Финляндия'`): нода записывается в панель
уже названной. Под полями — как её увидит покупатель: в Marvia «🇫🇮
Финляндия · fi-2», в Happ и Hiddify — то же с меткой покупателя в конце. То
же превью — в окне уже стоящей ноды при правке. Флаги в панели рисует
вшитый шрифт Twemoji: Windows своих флагов-эмодзи не рисует и показывает
вместо них две буквы.

**Страна по IP.** Не вписал страну — панель узнаёт её по адресу ноды сама:
при установке и у уже стоящих нод при сверке. Спрашивает она ipinfo.io, а
если тот молчит, ipwho.is; уходит туда только адрес сервера, адреса
покупателей — никогда. Вписанная руками страна главнее и не перезаписывается:
базы адресов ошибаются, сервер в Финляндии бывает «в Нидерландах». Заменяется
только слово, в котором страну не узнать («Пиюсн», опечатка): флага по нему
нет нигде, и покупатель видел бы «··». Кнопка «По IP»
в окне ноды подставляет страну адреса в поле, а сохраняешь ты. Код страны
(«FI», «ae») панель сама превращает в название — покупатель видит
«Финляндия · fi-1», а не «FI · fi-1»; у уже записанных нод это делается один
раз при запуске панели.

Хостер называет машину `vm-4823917-ubuntu`, и до сих пор ровно это видел
покупатель в списке серверов. Одна ручка чинит и это, и выбор страны:

```bash
curl -X PATCH https://panel.example.com/api/v1/nodes/3 \
  -H "Authorization: Bearer $MARVIA_ADMIN_TOKEN" \
  -d '{"name": "Амстердам-1", "country": "Нидерланды"}'
```

**Страну пишет продавец, а не определяет панель.** У хостеров адреса числятся
то в Нидерландах, то в США, и покупатель, выбравший «Финляндию», попадает в
Германию. Так же устроены Happ и Hiddify: страну там задаёт тот, кто продаёт.

Она встаёт первой в названии ноды — `Нидерланды · Амстердам-1`, — потому что
чужим клиентам её больше нечем передать: флажок они подбирают по тексту
названия. Нашему клиенту она приходит отдельным полем в подписке.

**Выключение вместо удаления.** При подозрении на блокировку нода должна уйти
из подписок, но остаться в панели:

```bash
curl -X PATCH https://panel.example.com/api/v1/nodes/3 \
  -H "Authorization: Bearer $MARVIA_ADMIN_TOKEN" -d '{"enabled": false}'
```

Расход по ней по-прежнему виден, покупатели её больше не получают, и решение
отменяется тем же запросом с `true`. Удаление уносит с собой всю статистику и
обратно не отыгрывается.

Адрес и ключи здесь не меняются: они пришли от самой ноды при регистрации, и
правка их руками означала бы ссылки, ведущие в никуда.

**Отпечаток TLS.** Клиент подключается к ноде с приветствием, похожим на
браузер, по умолчанию — на Chrome. По наблюдениям 2026 года (Xray-core
#6293, Хабр 1047442) фильтр учитывает отпечаток вместе с адресом и частотой
подключений, и на одних сетях проходят одни отпечатки, на других — другие.
Источник у наблюдений один, поэтому умолчание прежнее, а выбор — у продавца,
для каждой ноды отдельно: в карточке ноды или запросом.

```bash
curl -X PATCH https://panel.example.com/api/v1/nodes/3 \
  -H "Authorization: Bearer $MARVIA_ADMIN_TOKEN" -d '{"fingerprint": "firefox"}'
```

Допустимы `chrome`, `firefox`, `safari`, `ios`, `android`, `edge`, `qq`,
`360`; пустая строка возвращает Chrome. Те же имена уходят параметром `fp` в
ссылки для чужих приложений. Клиент сам отпечаток не перебирает: смена
отпечатка сразу после заморозки адреса, по тем же наблюдениям, её удлиняет.
Поэтому менять его стоит, только когда на ноду массово не подключаются, и
не чаще раза в несколько минут.

## Нода не работает: с чего начать

**Из панели.** «Ноды» → нода → **«Проверить ноду»**. Панель проходит путь по
шагам и на каждом, где плохо, говорит, что сделать: открыт ли порт, отвечает
ли он TLS и сходится ли сертификат прикрытия с его именем, сверяется ли нода
с панелью, не отстала ли версия, подключаются ли к ней покупатели (по их
отчётам), а у входа каскада — жив ли его выход. Проверка идёт с сервера
панели: блокировку у провайдера покупателя она сама не увидит — это видно
только по отчётам покупателей, поэтому они тоже шаг проверки. Для бота то же
— `POST /api/v1/nodes/{id}/check` с правом `nodes`: ответ — коды шагов и
числа, без текста.

В том же окне — раздел **«Протокол»**: маскировка (REALITY под каким сайтом,
TLS или WebSocket за CDN), порт, запасные имена прикрытия, ключи по краям,
QUIC и что уходит в подписку. Это то, что нода сообщила сама; править
маскировку надо флагами на ноде, отпечаток TLS — здесь же.

**На самой ноде**, от root:

На самой ноде, от root:

```bash
curl -fsSL https://raw.githubusercontent.com/jytt8u/marvia/main/scripts/node-check.sh | sh
```

Скрипт ничего не меняет — только смотрит и печатает: служба и её версия,
права на ключах, слушается ли порт, жив ли сайт прикрытия, не разошлись ли
часы (VP1 отбрасывает рукопожатия старше двух минут — нода тогда отказывает
всем подряд, ничего не объясняя), отвечает ли панель, и куда нода вообще
дозванивается. Вывод можно целиком переслать в поддержку: приватный ключ,
токен и содержимое `env` в нём не печатаются никогда.

**Про исходящую связность — отдельно.** Нода бывает здоровой со всех сторон
и всё равно бесполезной: панель отвечает, прикрытие живо, порт слушается, а
до части интернета с этой машины нет маршрута. Покупатель видит «подключено»
и пустой экран. В журнале при этом только `цель недоступна: i/o timeout` —
адреса там нет намеренно, иначе нода вела бы учёт, кто куда ходил.

Так и случилось на живой ноде в Хельсинки: хостер потерял маршрут в одну из
сетей Telegram (`91.108.56.0/22`), вторая (`149.154.0.0/16`) работала. Со
стороны это выглядело как «клиент не подключается», хотя подключался он
прекрасно. Проверка дозванивается до четырёх известных сетей и говорит, каких
из них не видно; чинится это не на ноде, а у хостера — ему нужен `traceroute`
до того адреса.

## Отчёты о доступности и выбор ноды

Панель стоит за границей и видит ноду живой ровно тогда, когда для телефона в
Иркутске она уже мертва. Единственный, кто знает правду, — само устройство.

**Клиент меряет ноды сам** и подключается к самой быстрой живой. Меряется не
время установки TCP, а время до работающего туннеля: заблокированная нода
обычно принимает соединение и молча роняет пакеты уже во время TLS, так что
проверка «порт открыт» показала бы её живой.

Если нода выбрана вручную, клиент подключается к ней сразу. Проверка остальных
не задерживает подключение: она остаётся доступной на экране серверов. Когда
выбранная нода недоступна, клиент проверяет запасные и показывает имя той,
через которую действительно идёт трафик.

**Результаты уходят панели** на `POST /sub/{token}/report` — тем же токеном
подписки. Админского токена на устройстве покупателя быть не должно ни при
каких обстоятельствах.

Панель складывает отчёты и ставит ноды в подписке в том порядке, в каком их
стоит пробовать. В интерфейсе у каждой ноды видно «сколько людей доходят» и
медианную задержку — продавец узнаёт о блокировке из панели, а не из
обращений в поддержку.

**«Режут».** Ноду не обязательно закрывают — её замедляют: подключиться
дают, а тянуть нечего. «Нода на связи» и «доходят» этого не покажут. Поэтому
в отчёте есть ещё время пробной загрузки (`fetch_ms`): за сколько нода
отдала покупателю порцию 128 КБ. Если у трёх и больше разных покупателей
медиана дольше 2,5 секунды (это около 400 кбит/с; живая нода отдаёт её за
доли секунды), панель считает ноду зарезанной: на карточке — «Режут» и
скорость, в окне ноды — «Скорость у покупателей», в проверке ноды — шаг
«Ноду режут» с советом поставить вход в России или сменить адрес, в
подписке нода встаёт ниже здоровых, а в телеграм приходит одно оповещение и
одно — когда снова тянет нормально. Один медленный покупатель повода не
даёт: это может быть его вайфай. Приложения постарше поля не шлют, а
панель постарше его не принимает — тогда приложение шлёт отчёт ещё раз без
него, и «доходят или нет» всё равно доходит.

### Почему отчёты не отключают ноды

Отчёты приходят от клиентов, то есть из недоверенного источника. Если бы
жалоба была командой, любой покупатель выкинул бы все ноды продавца из
подписок и убил сервис без всякой блокировки.

Поэтому три правила:

| Правило | Что оно предотвращает |
|---|---|
| от каждого подписчика хранится один последний отчёт на ноду | накрутку количеством сообщений |
| ноды не отключаются, а только переставляются в списке | уничтожение сервиса одним вредителем |
| проблемной нода считается от трёх разных жалобщиков | ложные срабатывания от одного человека с плохой связью |
| задержка двигает ноду в списке тоже только от трёх разных подписчиков | подъём заблокированной ноды наверх одним выдуманным замером |

Вредитель с одной подпиской в одиночку порядок нод в подписке не меняет:
его отчёт виден продавцу в сводке, но это один голос из трёх нужных.

## Пользователи, квоты и учёт

По умолчанию нода пускает любого, кто знает её публичный ключ. Для реальной
работы нужен файл пользователей — он же список того, кто и сколько может.

**Простой формат** — когда пользователей трое и лимиты не нужны:

```
# ноутбук
ЗДЕСЬ-ПУБЛИЧНЫЙ-КЛЮЧ-КЛИЕНТА-43-СИМВОЛА
```

**Полный формат** — с подписками и лимитами:

```json
{
  "users": [
    {
      "kind": "vp1",
      "secret": "ЗДЕСЬ-ПУБЛИЧНЫЙ-КЛЮЧ-КЛИЕНТА-43-СИМВОЛА",
      "label": "заказ 1043",
      "enabled": true,
      "expires_at": "2026-09-23T00:00:00Z",
      "traffic_limit": 107374182400,
      "max_ips": 3,
      "max_conns": 8,
      "speed_limit": 12500000,
      "account": "1043"
    },
    {
      "kind": "vless",
      "secret": "94183e3f-c094-4c62-9c8a-431fea85aa04",
      "label": "телефон",
      "enabled": true,
      "traffic_limit": 107374182400,
      "account": "1043"
    },
    {
      "kind": "trojan",
      "secret": "пароль",
      "label": "ноутбук",
      "enabled": true,
      "traffic_limit": 107374182400,
      "account": "1043"
    }
  ]
}
```

`kind` — вид доступа: `vp1` (умолчание, наш протокол), `vless` или `trojan`.
Последние два нужны, чтобы покупатель пользовался приложением, которое у него
уже стоит: v2rayNG, Hiddify, NekoBox. Нода понимает все три на одном порту и
различает их по первым байтам. UDP — игры, звонки, QUIC — по VLESS и Trojan
тоже проходит: и простой командой UDP, и через XUDP, которым Xray шлёт
датаграммы на все порты, кроме 53 и 443.

`account` связывает наборы в один аккаунт: квота, срок и лимит адресов у них
общие. Без него каждый набор получил бы свой лимит, и достаточно было бы
попросить второй конфиг, чтобы удвоить себе трафик.

Прежнее поле `public_key` по-прежнему понимается и означает то же, что
`secret` при `kind: vp1`.

```bash
./bin/marvia-node -users users.json
```

| Поле | Что делает |
|---|---|
| `enabled` | `false` — доступ приостановлен, статистика сохраняется |
| `expires_at` | конец подписки; пусто — бессрочно |
| `traffic_limit` | байт всего; 0 — без лимита |
| `max_ips` | со скольких разных адресов можно подключаться в течение часа |
| `max_conns` | одновременных соединений до ноды; с мультиплексированием одно устройство открывает до четырёх |
| `speed_limit` | потолок скорости в байтах в секунду; 0 — без ограничения. 12 500 000 это 100 Мбит/с |

`max_ips` — ответ на главную боль продавца: один купил, раздал конфиг
десятерым. Считать устройства напрямую нельзя, все предъявляют один ключ, а
вот разные адреса видно. Окно в час выбрано, чтобы переход с Wi-Fi на
мобильную сеть не упирался в лимит.

**Файл перечитывается на лету**, каждые 5 секунд по времени изменения:
панель или скрипт бота просто перезаписывают его. Если файл окажется битым,
нода продолжит работать по прошлому списку — отключить всех из-за опечатки
в конфиге хуже, чем на минуту отстать от изменений.

**Расход пишется рядом**, в `users.json.usage.json` (переопределяется флагом
`-usage`), каждые 30 секунд и при остановке. Перезапуск ноды не обнуляет
счётчики — иначе месячную квоту можно было бы сбросить, попросив продавца
перезагрузить сервер.

Клиент, исчерпавший квоту или подписку, отключается и при следующей попытке
получает **сайт-прикрытие** — ровно то же, что видит посторонний. Отвечать
по-разному на «ключ не найден» и «квота кончилась» нельзя: эта разница видна
снаружи и превращается в способ прощупать ноду.

Ключ клиента задаётся флагом `-key` или переменной `MARVIA_CLIENT_KEY`. Без него
клиент генерирует временный при каждом запуске — удобно для отладки, но нода
тогда не отличает одного клиента от другого.

**Кто на связи.** У каждого покупателя в панели и в `GET /api/v1/users`
стоит: соединений прямо сейчас, адресов за час (только при лимите
устройств — остальным нода адреса не считает) и когда был в последний раз.
Это ответ на «он вообще подключался?», и ничего сверх: адресов, стран и
истории подключений панель не получает. Нода кладёт два числа в тот же
отчёт, что и расход, панель верит им полторы минуты после последнего
отчёта — у замолчавшей ноды «на связи» не бывает никого.

«Был на связи» ставится и по трафику, а не только по живым соединениям:
нода отчитывается раз в пятнадцать секунд, и сессия короче тика в отчёт о
присутствии не попадает. Без этого панель отвечала «не подключался ни разу»
про человека, у которого расход уже записан. Отозвать одно
устройство из нескольких нельзя: у них общий ключ, различить их нечем;
для этого есть «Сменить ключ», который меняет ключ всем сразу.

## Панель

Управляющий слой: подписчики, ключи, ноды, статистика. Пользовательский трафик
через панель не идёт никогда — её домен светится только в момент обновления
подписки.

```bash
./bin/marvia-panel -new-token                  # выпустить админский токен
MARVIA_ADMIN_TOKEN=<токен> ./bin/marvia-panel -db marvia-panel.db -sub-base https://sub.example.com
```

Панель отдаёт голый HTTP и **обязана стоять за обратным прокси с TLS**: по её
API ходят токены, а в ответах уезжают приватные ключи подписчиков.

### Веб-интерфейс

Открой корень панели в браузере и введи админский токен — он останется в этом
браузере. Страница вшита в бинарник: копировать на сервер по-прежнему нужно
один файл.

Что там есть:

- **Выдать доступ** — метка, срок, квота, лимит устройств, потолок скорости и
  галочки видов доступа. После создания сразу открывается окно со всеми ссылками и кнопками
  «Копировать»: ссылка для нашего клиента, адрес подписки и прямые ссылки на
  каждую ноду. Это и есть повседневная работа продавца — выдал, скопировал,
  отправил.
- **Список подписчиков** — расход с полосой заполнения квоты, срок в днях,
  какие виды доступа выданы. Кнопки: ссылки, продлить на 30 дней, отключить,
  выпустить ещё один доступ, удалить.
- **Ноды** — адрес, SNI, когда последний раз выходила на связь. При добавлении
  показывается готовая команда запуска с токеном ноды.

Страница отдаётся с жёсткой политикой безопасности: разрешён ровно один
скрипт, наш, опознаваемый по одноразовому значению, внешние адреса запрещены
вовсе. Причина простая: на этой странице лежит админский токен, и любой чужой
скрипт в этом origin означал бы полный доступ к панели. По той же причине все
данные ставятся в разметку как текст — метка подписчика вида
`<img src=x onerror=...>` отрисуется буквами, а не выполнится.

## Ссылка подписки в браузере

### Покупателю

Откройте выданную продавцом ссылку `https://…/sub/…` в браузере. Вместо
строки base64 появится страница доступа: работает ли он, когда закончится
срок и сколько трафика осталось. Дата показана с часами и обозначением UTC;
если ограничения нет, так и написано. Израсходованная квота не становится
отрицательным остатком. Даже после конца срока или отключения доступа
страница остаётся доступна, чтобы вы могли связаться с продавцом.

В Happ, v2RayTun или Hiddify выберите добавление подписки по ссылке и
вставьте адрес из поля на странице. Можно отсканировать QR-код из самого
приложения. В QR и поле находится один и тот же адрес с `?format=base64`:
он всегда отдаёт подписку, даже если приложение представляется браузером.
QR генерируется панелью, без обращения к чужому сервису. Ссылка и QR дают
доступ к подписке — не публикуйте их.

Если продавец выложил Marvia, здесь же появятся кнопки скачивания Windows
и Android **с его домена**. Для вашей системы ссылка идёт первой. Для
подключения через VP1 нужен личный ключ `marvia://` из сообщения продавца:
панель не хранит его приватную часть и не может восстановить её по ссылке
подписки. На странице нет кнопки, обещающей выдать такой ключ заново.

«Продлить» и «Поддержка» появляются только тогда, когда продавец указал
соответствующие ссылки. Они открывают его сайт или Telegram; сама панель
платежи не принимает. Объявление продавца отображается обычным текстом.
Русский или английский язык выбирается по предпочтениям браузера;
при отсутствии подходящего языка — русский.

### Продавцу

Для работы QR задайте правильный публичный адрес панели через `-sub-base`.
Положите приложения в `dist`, как описано ниже; отсутствующий файл и
одиночный EXE без драйвера не превращаются в кнопку скачивания. Поддержку,
продление и объявление задайте в разделе связи с покупателем в панели или
через `PUT /api/v1/seller` (см. «Поддержка, продление и объявление для
покупателей»). Настройки общие со ссылками и объявлениями в приложениях.

Страница открывается только при явном `Accept: text/html` с ненулевым
приоритетом и браузерном User-Agent. Happ, v2RayTun, Hiddify, Marvia,
стандартный HTTP-клиент Go и curl продолжают получать прежние форматы;
маркер приложения имеет приоритет над браузерной приставкой User-Agent.
Запросы из приложения с `Sec-Fetch-Mode: cors` или `Sec-Fetch-Dest: empty`
тоже остаются подписками. Любой явный `format` выключает HTML:
`json` — для Marvia, `raw` — ссылки текстом, `base64` — обычная подписка.

Проверка Hiddify опирается на его
[User-Agent в исходнике](https://github.com/hiddify/hiddify-app/blob/88d2449d2a3379a4d2f9fc1c83285229931b8176/lib/core/model/app_info_entity.dart)
и [HTTP-клиент](https://github.com/hiddify/hiddify-app/blob/88d2449d2a3379a4d2f9fc1c83285229931b8176/lib/core/http_client/dio_http_client.dart).
Для Happ сверены [запросы в тестах обработчика 3x-ui](https://github.com/MHSanaei/3x-ui/blob/d1b60799ecd46616c2c62afc8e166b1480e7bc84/internal/sub/happ_test.go)
и [официальная настройка подмены User-Agent](https://www.happ.su/main/dev-docs/app-management#user-agent).
Исходники закрытых Happ и v2RayTun недоступны, поэтому тесты проверяют
несколько вариантов их User-Agent со всеми вариантами Accept, включая
`text/html`, а не полагаются на один заголовок конкретного выпуска.
Если в приложении вручную подменить **все** заголовки на браузерные,
сервер отличить его от браузера не сможет; для этого случая используйте
ссылку с `?format=base64` со страницы.

Страница не ставит cookie, не запрашивает сторонние ресурсы и не записывает
просмотр или IP в журнал панели. Шаблон вшит отдельно, `html/template`
экранирует текст, стили допускаются только с новым nonce на каждый ответ.
Скрипты, сетевые картинки, внешние шрифты, формы и встраивание во фрейм
запрещены CSP. Ответ не кэшируется, а переход к поддержке или оплате не
передаёт ссылку подписки в Referer. Если перед панелью стоит обратный прокси,
отключите его журнал доступа для `/sub/`: его настройки панель не меняет.

## Приложения раздаёт панель

Покупатель качает приложение **с домена продавца**, а не из магазина и не с
github. В августе 2026 провайдеры начали рубить загрузку из Google Play и App
Store, объясняя это блокировкой международных CDN, — а github раздаётся ровно
через такой же CDN. Ссылка «скачай приложение» отваливается первой, и продавец
теряет человека, который уже заплатил.

Установщик кладёт `marvia-android.apk`, `marvia-windows-setup.exe` и полный
`marvia-windows.zip` в `dist` рядом с панелью. Для Windows панель сначала
выбирает установщик, затем ZIP. Если остался только старый одиночный EXE,
ссылка Windows скрыта: такой файл без драйвера не является готовым комплектом.
Дальше ссылки приходят сами — вместе с доступом:

```json
{
  "links": {
    "account": "marvia://…",
    "subscription": "https://panel.example.com/sub/…",
    "apps": {
      "android": "https://panel.example.com/sub/…/app/android",
      "windows": "https://panel.example.com/sub/…/app/windows"
    }
  }
}
```

**Ссылка живёт под токеном подписки**, а не на открытом пути. Открытый файл
`.apk` на домене панели признаётся первому же сканеру, что это панель обхода
блокировок; у покупателя токен есть — он пришёл в той же ссылке, что и доступ.

Ссылки на невыложенное приложение не бывает: ссылка, ведущая в никуда, хуже её
отсутствия — покупатель по ней сходит и придёт с вопросом. Что выложено,
видно продавцу:

```bash
curl https://panel.example.com/api/v1/apps -H "Authorization: Bearer $MARVIA_ADMIN_TOKEN"
```

В ответе размер и sha256 каждого файла — чтобы сверить, что лежит именно то,
что скачивал.

**Клиент сам замечает, что устарел.** Рядом с приложением лежит файл
`marvia-android.apk.version` (и такой же у установщика или `.zip`) — одна строка с версией.
Его пишут установщик и `upgrade.sh`: приложения качаются из того же релиза,
что и панель, и версия им известна. Подписка отдаёт версию клиенту вместе со
ссылкой; тот сравнивает со своей и, если на панели новее, показывает «есть
новая версия» со ссылкой на домен продавца — не в магазин. Только новее, не
«другая»: выложил старую сборку — никого на неё не позовёт. Нет файла — нет
версии, и клиент молчит; положил приложение руками — положи и версию.

Панель и оба клиента используют общий порядок версий: `alpha.5 < alpha.6 <
beta.1 < rc.1 < выпуск без хвоста` при одинаковом основном номере.
Номер после точки сравнивается как число (`alpha.9 < alpha.10`), а метаданные
после `+` не меняют порядок. Поэтому новая тестовая сборка в `dist` тоже
показывает предложение обновиться; равная или более старая — нет.
Уже установленной alpha.5 с прежним сравнением эта правка сама не поможет:
первый переход нужно выполнить вручную по ссылке приложения от продавца.

`upgrade.sh` обновляет и `dist` целиком: бинарник ноды для команды
установки, генератор ключей, оба приложения с версиями. Раньше он менял
только саму панель, и новая нода после обновления ставилась со старым
бинарником — молча.

## Телеграм-бот пишет продавец

Бота продавец делает сам: у каждого свои тарифы, свой приём денег, своя база и
свой разговор с покупателем — и своя ответственность за всё это. Наше дело —
панель и API, как и у остальных панелей.

В помощь — рабочий пример в [examples/tg-bot](examples/tg-bot): продажа,
продление, остаток трафика, выдача новой ссылки, напоминание за три дня до
конца, оплата звёздами телеграма или вручную с подтверждением. Копируй каталог
и переделывай; в релизы он не входит и поддержкой не покрыт.

Три вещи в API неочевидны и стоят продавцу денег, если сделать иначе:

- **покупатель ищется по `external_id`** — обычно telegram id. Повторная
  продажа тому же ключу не заводит второго подписчика;
- **срок считает панель**: `extend_by` прибавляет к остатку, поэтому
  продливший заранее ничего не теряет, а два одновременных платежа не затирают
  друг друга;
- **номер платежа уходит в `Idempotency-Key`** — и повтор уведомления от
  платёжной системы не выдаёт второй срок за одни деньги. Это работает и на
  продлении, и на первой продаже.

### API для телеграм-бота

Всё под токеном в заголовке `Authorization: Bearer <токен>`. Боту выдаётся
**свой ключ**, а не админский токен: `POST /api/v1/keys` с правом `users`.

Отдать боту админский токен — значит дать право снести все ноды вместе со
статистикой и увести базу с секретами vless и trojan. А при утечке отозвать
его нельзя, не выкинув из панели себя самого: это один и тот же токен.

| Право ключа | Что даёт |
|---|---|
| `users` | покупатели: завести, продлить, отключить, удалить, выдать ссылки |
| `nodes` | ноды: переименовать, выключить, удалить (добавить и пригласить — только админ: новая нода получает секреты всех покупателей) |
| `read` | только смотреть; входит в любое другое право. Токен подписки и секреты vless и trojan видны только с `users` |

Боту хватает `users`. Выпуск, список и отзыв ключей — только под админским
токеном: ключ, умеющий выпускать ключи, ничем не отличается от админского.
В списке видно, когда каждым пользовались, — по этому и понятно, какой живой.

| Метод | Путь | Что делает |
|---|---|---|
| `POST` | `/api/v1/users` | завести подписчика, вернуть ключ и ссылку |
| `GET` | `/api/v1/users` | список с расходом |
| `PATCH` | `/api/v1/users/{id}` | продлить, отключить, поменять лимиты |
| `DELETE` | `/api/v1/users/{id}` | удалить |
| `POST` | `/api/v1/users/{id}/credentials` | выдать доступ ещё на одно устройство или для другого протокола |
| `POST` | `/api/v1/users/{id}/sub-token` | сменить адрес подписки, когда её ссылку раздали |
| `POST` | `/api/v1/users/{id}/renew` | продлить по тарифу: срок, лимиты и новый период расхода |
| `POST` | `/api/v1/users/{id}/reset-traffic` | обнулить расход, не трогая срок |
| `POST` | `/api/v1/users/{id}/freeze` | заморозить: доступ выключен, срок при разморозке сдвинется на паузу |
| `POST` | `/api/v1/users/{id}/unfreeze` | разморозить; не заморожен — 409 |

| `GET` · `PUT` | `/api/v1/webhooks` | вебхуки для бота: адреса, секрет подписи (только админским токеном) |
| `GET` · `PUT` | `/api/v1/backups` | копии вне сервера по расписанию (только админским токеном) |

| `POST` | `/api/v1/credentials/{id}/rotate` | сменить утёкший ключ, оставив набор на месте |

Подробный справочник для автора бота — [docs/bot.md](bot.md): продажа,
продление, поиск покупателя, коды ответов и грабли, на которые он иначе
наступит.

**Бота пишет продавец, а не мы.** У каждого своя оплата, свои тарифы, свой
язык общения с покупателем. Наше дело — чтобы на этом пути не было граблей, и
две из них убраны прямо в API.

`external_id` — идентификатор покупателя в системе продавца, обычно telegram
id. Повторный запрос с тем же ключом **ничего не создаёт**: панель отвечает
успехом, возвращает существующего подписчика и ставит `"created": false`.
Платёжные системы повторяют уведомление, когда бот не ответил, а бот мог упасть
ровно между вызовом панели и записью у себя — и без этого одна оплата давала бы
два доступа.

`extend_by` — продление, а не назначение срока. Прибавляет к тому, что
осталось: продливший за неделю до конца эту неделю не теряет, а вернувшийся
через полгода не покупает месяц, истёкший пять месяцев назад. Считается одной
транзакцией: бот, который читает срок, прибавляет месяц и пишет обратно, теряет
один платёж при двух одновременных — и узнаёт об этом от покупателя.

Продать месяц одним запросом:

```bash
curl -X POST https://panel.example.com/api/v1/users \
  -H "Authorization: Bearer $MARVIA_ADMIN_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"label":"заказ 1043","traffic_limit":107374182400,"max_ips":3,"kinds":["vp1","vless","trojan"]}'
```

`kinds` — какие виды доступа выдать. Пусто означает только `vp1`. Продавцу,
переводящему покупателей с чужой панели, обычно нужны все три.

В ответе `issued` с секретами и `links` с готовыми ссылками:

```json
{
  "links": {
    "account": "marvia://...",
    "subscription": "https://sub.example.com/sub/<токен>",
    "stock": [
      "vless://<uuid>@msk.example.com:443?encryption=none&fp=chrome&security=tls&sni=msk.example.com&type=tcp#msk",
      "trojan://<пароль>@msk.example.com:443?fp=chrome&security=tls&sni=msk.example.com&type=tcp#msk"
    ]
  }
}
```

`account` — для нашего клиента, `stock` — для приложений, которые у покупателя
уже стоят. Бот не должен склеивать ссылки сам: одна ошибка в параметрах — и
покупатель приходит с «не работает», а продавец не понимает, в чём дело.

**Секреты отдаются ровно один раз.** Для `vp1` панель приватную часть вообще
не хранит: утечка базы не даёт доступа ни к одному клиенту. Для `vless` и
`trojan` так не выйдет — там секрет это строка, которую обязаны знать обе
стороны, и панель хранит её в открытом виде, потому что ноде её надо отдать.
**Значит база панели с записями чужих протоколов — настоящий секрет, и её
утечка равносильна выдаче доступа всем таким клиентам.** Это и есть цена
совместимости.

### Ноды и панель

```bash
./bin/marvia-node -panel https://panel.example.com -panel-token <токен ноды> ...
```

Нода раз в 15 секунд сдаёт расход и забирает свежий список. Если панель
недоступна — работает по последнему полученному списку: потерять панель на час
неприятно, отключить из-за этого всех клиентов недопустимо.

**Общая квота при нескольких нодах.** Каждая нода считает только свой трафик,
поэтому панель выдаёт ей лимит за вычетом израсходованного на других. Иначе
квоту в 100 ГБ можно было бы потратить на каждой ноде отдельно.

**Несколько устройств — один аккаунт.** У телефона и ноутбука разные ключи: их
видно по отдельности и любой отзывается отдельно. Но квота, срок и лимит
адресов у них общие, иначе достаточно попросить второй конфиг, чтобы удвоить
себе трафик.

### Подписка

`GET /sub/{token}` отдаёт браузеру страницу доступа, а приложениям — ссылки
на все ноды, свёрнутые в base64. В заголовке `Subscription-Userinfo` едет остаток
трафика и дата окончания: по нему приложения рисуют полоску квоты. Если
продавец задал поддержку, «Продлить» и объявление, рядом едут `Support-Url`,
`Profile-Web-Page-Url` и `Announce`, а в `?format=json` — поля `support_url`,
`renew_url`, `announce` (см. «Поддержка, продление и объявление для
покупателей»).

| Запрос | Что отдаёт | Кому |
|---|---|---|
| `/sub/{token}` с браузерным User-Agent и `Accept: text/html` | страница срока, трафика, QR и ссылок продавца | покупатель в браузере |
| `/sub/{token}` из приложения или curl | base64 со ссылками `vless://` и `trojan://` | Happ, v2RayTun, v2rayNG, Hiddify, NekoBox |
| `/sub/{token}?format=base64` | base64 независимо от заголовков | импорт ссылки и QR со страницы |
| `/sub/{token}?format=raw` | то же, но без base64 | для отладки глазами |
| `/sub/{token}?format=json` | список нод со ссылками `marvia://` и остатком квоты | наш клиент |

**Наши ссылки в обычную подписку не попадают намеренно.** Чужие клиенты не
знают схемы `marvia://`, и часть из них спотыкается на незнакомой строке и не
принимает подписку целиком — то есть ломается именно у тех, ради кого всё
затевалось.

Приватного ключа VP1 в подписке нет: покупатель получил его один раз в
`account`. Обычная подписка содержит UUID VLESS и пароли Trojan, поэтому
её адрес, содержимое и QR нельзя публиковать.

### Стенд: как нода выглядит снаружи

Оценки в protocol.md §10 — наши собственные, пока их не проверил чужой
классификатор. Для этого есть `scripts/stand.sh`: запускается на Linux с той
стороны, откуда ходят покупатели, пишет трафик до ноды в pcap, прогоняет
запись через nDPI и Zeek с JA4 и щупает ноду так, как это делают сканеры —
TLS без метки, мусор, чужой QUIC.

```bash
sudo sh scripts/stand.sh -server node.example.com:443 -pubkey <ключ ноды> \
    -sni cover.example.com -reality-pbk … -reality-sid … -quic \
    -key <приватный ключ покупателя>
```

`-key` — из ссылки покупателя `marvia://КЛЮЧ@…`: без него ключ временный,
нода с базой покупателей его не знает и отвечает сайтом-прикрытием, как
чужому; трафика внутри туннеля не будет. Заведи покупателя на сутки и удали
после.

nDPI собирай из исходников, ветка 4.10 или новее: `libndpi-bin` из Ubuntu
22.04 — это 4.2 2022 года, он не знает ни ECH, ни ALPS, метит любой
современный Chrome как подозрительный и не считает JA4.

Что должно получиться: nDPI видит TLS к сайту-прикрытию, а не «unknown» и не
прокси; JA4 совпадает с текущим Chrome на ja4db.com; на TLS без метки
отвечает сайт-прикрытие со своим сертификатом; на чужой QUIC — тишина. Чего
не хватает на машине, стенд пропускает с пометкой: даже один pcap уже можно
приложить к issue.

**Замер 14 сентября 2026**, Дубай → Хельсинки, nDPI 4.10, 28 МБ через
туннель: один поток, `TLS`, `Chrome`, SNI сайта-прикрытия, JA4
`t13d1516h2_8daaf6152771_d8a2da3f94cd` — это JA4 настоящего Chrome 130+.
Единственная пометка — «TLS Susp Extn 17613»: расширение ALPS, которое
Chrome прислал бы точно так же, а nDPI ещё не знает. Зонды: TLS без метки —
сайт с сертификатом DigiCert, мусор — соединение закрыто.

напрямую 86 Мбит/с, через туннель одним потоком 83 — туннель отдаёт путь
почти целиком, а потолком был канал машины в Дубае. Замер на 400 Мбит/с
нужен с той стороны, где канал шире: из России, с домашней машины.

### Отклик ноды и время подключения

«Отклик» в Android и Windows — оценка ядра системы для TCP-соединения
туннеля до ноды (`TCP_INFO` в Linux, `SIO_TCP_INFO` в Windows): сглаженное
время подтверждения. Где сокета TCP нет (QUIC, WebSocket) — последний
запрос-ответ внутри туннеля (служебный Ping мультиплексора). Рукопожатия
и скачивание пробной порции в него не входят. Это отклик ноды, а не
игрового сервера, не ICMP-пинг и не непрерывный мониторинг. Замер
выполняется при проверке нод; кнопка обновления в списке серверов
запускает новую проверку. После подключения отклик текущей ноды
обновляется по интервалу из настроек Android.

Почему не Ping мультиплексора. Он идёт по тому же соединению, что и
трафик, и во время скачивания стоит в очереди за данными: отклик прыгал
до сотен миллисекунд и секунд, а дольше трёх секунд считался неудачей — и
уведомление до следующего замера оставалось без отклика. Оценка ядра
очередь внутри туннеля не включает, а очередь в сети — включает. Ping
мультиплексора при этом уходит в фоне: без отправленных данных ядро не
заметило бы обрыва. Соединение считается замолчавшим, и отклик
скрывается, как раньше, когда подтверждений нет дольше пяти секунд
(Linux) или между двумя замерами дважды истёк таймер повторной отправки и
не пришло ни байта (Windows).

В списке отдельно показывается «Подключение» — время подготовки туннеля.
«Отклик не измерен» означает отсутствие успешного замера, а не нулевую
задержку. Число 600 мс из прежних версий могло включать подготовку или
передачу пробных данных и напрямую с новым откликом не сравнивается.

Служебный Ping уже поддерживается мультиплексором старых нод: изменения
формата VP1 и обновления сервера для этого исправления не требуются.

После выбора языка открывается главный экран с исходным знаком Marvia.

### Приложения и сайты на Android

«Настройки» → «Приложения и сайты» решают, что идёт мимо туннеля:

- **Российские сайты** — подсети России напрямую, по списку от панели.
- **Свои адреса** — адрес, подсеть или сайт, по строке: рабочий сервер,
  роутер, игра. Сайт превращается в адреса при подключении; у больших
  сайтов за CDN адреса меняются, и часть запросов может уйти в туннель.
  Сети шире /8 (IPv6 — шире /16) не принимаются: такое правило выключило бы
  VPN целиком. Нераспознанные строки показываются, а не пропадают молча.
- **Без VPN — без интернета** ведёт в системные настройки VPN: постоянный
  VPN и блокировку соединений без него включает только сам Android.
- **Приложения** — мимо туннеля, только выбранные или выключено. Системные
  приложения скрыты, пока не нажать «Системные»; уже выбранные видны всегда.

Исключать адреса умеет Android 13 и новее; на старых строк российских
сайтов и своих адресов нет — остаётся выбор приложений.

Вибрации в приложении нет: ни при подключении, ни при выборе.


### Статистика Android

Главный экран показывает объём полезных данных за сегодня (24 столбика по часам), длительность текущей сессии и суммарную скорость загрузки и отправки. Счётчики учитывают данные потоков внутри туннеля, включая запросы DNS, без транспортного шифрования и повторных передач. История объёмов сохраняется только на телефоне; адреса и названия приложений в неё не входят. При остановке процесса между опросами последняя неполная выборка может потеряться. Квота продавца показывается отдельно и может отличаться.

В оформлении сначала видны шесть тем и постоянный образец главной с кнопкой и статистикой; остальные открываются через «Все темы», подробные настройки — отдельной кнопкой.

### Windows: одна копия и статистика

Повторный запуск открывает уже работающее окно без нового туннеля и значка.
Старая сборка без этой защиты должна быть завершена через «Выйти» в меню
каждого её значка. Затем запускается новый EXE. Крестик только прячет окно.

Переключение трея и полного окна не перезагружает страницу и не теряет
введённый ключ. Мини-окно учитывает масштаб экрана и доступную рабочую область.

В статистике видны приём/отдача, длительность, последний измеренный RTT ноды,
дневной расход по часам, средние скорости и пики сессии. Снятие объёмов и
скоростей — раз в пять секунд; пики относятся к этим интервалам, а не к
максимальной пропускной способности канала. Средняя скорость — объём сессии,
делённый на её длительность. Поднятие соединения не выдаётся за пинг.
После неудачного замера отклика или проверки доступности ноды прежний RTT
сбрасывается. Вместо числа, измеренного до потери сети, показывается «—»;
отдельные результаты установки соединения и скорости не удаляются.
Дневной расход сохраняется в `%APPDATA%\Marvia\traffic.json`, обычно раз в
минуту и при отключении; аварийный выход может потерять последнюю минуту.
В файле нет сайтов, IP, ключей или списка приложений. День и часы — местные.

### Подписки и выбор приложений

Клиенты отказывают перенаправлению с HTTPS на HTTP при загрузке подписок и
списка обхода. Начальная HTTP-подписка по-прежнему допускается для старых
панелей, но её токен не защищён TLS: используйте HTTPS.

На Android режим «только выбранные» останавливает подключение, если все
сохранённые пакеты удалены. Обновите выбор в настройках приложений. Если
осталась хотя бы одна выбранная программа, туннель применяется только к ней
и другим сохранившимся выбранным пакетам. Явно пустой выбор сохраняет прежний
режим всех приложений, о котором предупреждает экран.


### Кэш и смена сети в alpha.4

Чужая подписка использует полный отпечаток своего адреса в имени и содержимом
кэша, включая сведения продавца. Старый файл без привязки не читается даже
для экрана поддержки: после обновления нужен один успешный запрос панели.
Собственный новый кэш по-прежнему доступен без панели; удаление подписки
стирает оба формата. Дата из будущего не считается свежей.

Android передаёт смену физической сети ядру; повторные свойства той же сети
не перезапускают VPN. Старая попытка замера, переключения или запуска после
остановки не должна менять состояние нового туннеля. Это не гарантирует
фиксированный пинг на мобильном интернете; нужны измерения на устройстве.
